# Как продолжить работу над CrabLogic на другом компьютере

Репозиторий: https://github.com/phazz1980/CrabLogic (ветка `main`). Всё, что нужно для кода, лежит в git.
Не лежит в git: инструменты, тяжёлые сборочные папки, ваши пароли и память Claude. Ниже — что поставить и что
перенести руками.

## 1. Что поставить (Windows 10/11 x64)

1. **Git** и **GitHub CLI** (`gh`). Войдите: `gh auth login`. Имя и почта для коммитов:
   `git config --global user.name "phazz1980"` и `git config --global user.email "<ваша почта>"`.
2. **Visual Studio 2022 Build Tools** (рабочая нагрузка «Разработка классических приложений на C++») — нужна
   MSVC-линковщику Rust.
3. **Rust** через `rustup` (тулчейн `stable-x86_64-pc-windows-msvc`), затем:

   ```powershell
   rustup component add clippy rustfmt
   cargo install ldproxy espflash espup --locked
   ```

4. **Python 3** (3.10–3.12, в `PATH`): сборка ESP-IDF создаёт для себя виртуальное окружение.
5. Для мастера на ESP32-C3 (RISC-V):

   ```powershell
   rustup toolchain install nightly-2026-09-20 --component rust-src
   ```

6. Для мастера на классическом ESP32 (Xtensa), один раз:

   ```powershell
   espup install --std --targets esp32
   ```

   `espup` пропишет `LIBCLANG_PATH` в переменные пользователя; в уже открытой консоли его нет — откройте новую
   или выполните `%USERPROFILE%\export-esp.ps1`.
7. Драйвер USB-UART плат (CP210x или CH340 — смотря какая плата), чтобы появился COM-порт.

Без плат и без прошивки (только редактор, проверка схем, симуляция, тесты) достаточно пунктов 1–3.

## 2. Клонирование

Репозиторий кладите **близко к корню диска и с коротким путём** (например, `D:\CrabLogic`): ESP-IDF на Windows
не принимает пути сборки длиннее 88 символов.

```powershell
git clone https://github.com/phazz1980/CrabLogic.git D:\CrabLogic
cd D:\CrabLogic
```

## 3. Проверка, что всё работает

```powershell
cargo build -p crab-cli -p crab-editor
cargo test -j 2                       # около 950 тестов; -j 2 — если мало файла подкачки
cargo test --manifest-path firmware/master-rs/Cargo.toml     # тесты мастера на ПК
cargo run -p crab-cli -- check examples/pump                 # проверка примера
cargo run -p crab-editor                                     # редактор
```

Перед завершением любого шага: `cargo fmt`, `cargo clippy --all-targets`, `cargo test` (правила — в `CLAUDE.md`).

## 4. Прошивка мастера (нужны платы и тулчейны из пункта 1)

В `.deps/` (не в git) положите, как описано в `firmware/master-rs/README.md`:

- `.deps/wamr/` — `git clone --depth 1 -b WAMR-2.4.5 https://github.com/bytecodealliance/wasm-micro-runtime .deps/wamr`;
- `.deps/wamrc/wamrc.exe` — из `wamrc-2.4.5-x86_64-windows-2022.zip` с релиза WAMR (или путь в `CRAB_WAMRC`).
  `wamrc` для Xtensa редактор скачивает сам в `tools\wamrc-esp-<версия>\`.

Сборка (папка сборки — `.m\` в корне репозитория, первая сборка скачивает ESP-IDF v5.3.3 в `.embuild\`:
несколько ГБ и 10–30 минут):

```powershell
cd firmware\master-rs
cargo build --release                                              # ESP32-C3
cargo +esp build --release --target xtensa-esp32-espidf            # ESP32
```

Заливка мастера и модулей (из корня репозитория; `crablogic` — это `targetelease\crablogic.exe` или `cargo run -p crab-cli --`):

```powershell
crablogic flash-master --chip esp32c3 --firmware <папка с firmware\> -p COM5
crablogic gen-wasm examples/pump --upload -p COM10
crablogic find          # найти платы в локальной сети
crablogic monitor <проект> -p COM5
```

Готовый дистрибутив (`dist\CrabLogic.zip`) собирает `scripts\build-dist.ps1 -BuildMaster` (редактор должен быть
закрыт, иначе Windows не даст заменить `.exe`).

## 5. Что перенести вручную (в git этого нет)

| Что | Где лежит | Зачем |
|---|---|---|
| Пароли Wi-Fi и MQTT (локальные значения), ключи ИИ (`editor.toml`, открытым текстом), темы редактора | `%APPDATA%\CrabLogic\` | в файлы проектов они не попадают; на новом ПК введите заново или скопируйте папку (ключи передавайте только безопасным способом) |
| Настройки стендов `bench` | `bench\secrets.toml` (образец — `bench\secrets.example.toml`) | Wi-Fi и MQTT для сетевых стендов |
| Отчёты замеров | `bench\*.toml` | в git только `bench\history.md`; сравнивать со старыми отчётами нечем без копии |
| Память Claude Code | `%USERPROFILE%\.claude\projects\D--CrabLogic\memory\` | накопленные договорённости; скопируйте в папку `projects\<путь проекта с заменой \ на ->\memory` на новом ПК (имя папки зависит от пути репозитория) |
| Токен бота Telegram | секрет репозитория `TELEGRAM_BOT_TOKEN` на GitHub | публикация релизов в канал (`.github\workflows\telegram-release.yml`) |
| Инструменты симуляции блоков | `tools\` (zig, w2c2-src, riscv-тулчейн) | локальные, в git не попадают; нужны только для симуляции блоков пользователя |

`CLAUDE.md` и `AGENTS.md` лежат в репозитории: Claude Code читает их сам при открытии папки.

## 6. Где что читать

- `CLAUDE.md` — правила работы (язык, стиль, проверки, замеры, надёжность кода на плате).
- `Архитектура и план.md` — архитектура и решения; читайте по нужному разделу.
- `specs/<фича>/` — спецификации (`spec.md`, `plan.md`, `tasks.md`); отмеченные `[x]` задачи — сделанные.
- `help/*.md` — справка программы; правится вместе с кодом.
- `bench/history.md` — история замеров скорости и ОЗУ на платах.
- `firmware/master-rs/README.md` — мастер на плате и его сборка.

## 7. На чём остановились (19.11.2026)

- Версия в `Cargo.toml` — 2.1.0, опубликован релиз v2.1.0. После него в `main` ещё: Modbus деревом
  (master → slave → теги), свой IP у каждого slave, до 32 slave, значки без рамки, группы OLED/LCD, команда `name`.
  Новый релиз — по просьбе; версию выбирает пользователь (предложить 2.2.0).
- `specs/modbus-tree/tasks.md` — все задачи отмечены. **Не проверено в окне редактора:** дерево Modbus (панель,
  перетаскивание тега на лист, шаг отмены, поля IP и порта). Не сделаны `bench` и замер ОЗУ C3 на нескольких
  соединениях Modbus, проверка Ethernet и RTU.
- Автопубликация релизов в Telegram-канал: Action добавлен, нужен секрет `TELEGRAM_BOT_TOKEN`
  (`gh secret set TELEGRAM_BOT_TOKEN --repo phazz1980/CrabLogic`), потом ручной запуск для проверки.
- Платы разработчика: ESP32-WROOM и ESP32-C3 (COM10 и COM5 на прежнем ПК; на новом номера свои). Пины, ОЗУ и
  ограничения C3 — в справке и в `specs/`.
- Прочие незакрытые места: перевод справки и строк интерфейса на другие языки, LoRa (`specs/lora-e220`,
  задача 10), этап ESP32-S3 (`specs/esp32s3`), копия проекта на плате (`specs/ota`).
