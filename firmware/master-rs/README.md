# Rust-мастер CrabLogic

Экспериментальный мастер для ESP32-C3 — этап 3 плана `specs/wasm-kernel`: ядро `crab-kernel` и WAMR
(классический интерпретатор и AOT с выполнением из флеша) на ESP-IDF. Проект намеренно вне основного
Cargo workspace: у ESP-IDF свой тулчейн, и он не должен менять обычную сборку CrabLogic.
Основным мастером пока остаётся C++-мастер.

## Что есть сейчас

- сборка под ESP-IDF (`esp-idf-svc`), WAMR 2.4.5 как компонент ESP-IDF (`components/crab_wamr`);
- бэкенд `Engine` ядра поверх WAMR (`src/board/engine.rs`): импорты `crab.*` — raw-нативы, права и версия
  ABI проверяются при загрузке, trap превращается в сообщение;
- модули хранятся в разделе `crabmod` (`src/storage.rs`): области переменной длины, заголовок 256 Б + образ
  (`.wasm` или XIP-`.aot`, который исполняется прямо из раздела); новая версия пишется рядом со старой и
  заменяет её без сброса выходов; после перезагрузки модули запускаются сами;
- команды по USB, как у C++-мастера (`src/protocol.rs`): `put`, `list`/`stats`, `tick`, `del`, `swap`, `rmax`,
  `log`, и своя `info` (место в `crabmod` и список образов). Заливка листа из редактора и
  `crablogic gen-wasm --upload` работают без правок;
- команды отладки, тоже как у C++-мастера: `out` (значения выходов), `ev` (изменения выходов 0/1 с метками
  времени платы), `force`/`unforce` (форсировка выхода; сама форсировка и события живут в `crab-kernel`),
  `in`/`param`, `reset`, `pins` (занятые пины, их безопасное состояние и уровень);
- сбой модуля (trap, слишком долгий шаг): его выходы уходят в `on_fault`, модуль останавливается и
  перезапускается с чистого образа через паузу 1, 2, 4… до 30 с (`src/restart.rs`); проверочный модуль —
  `modules/fault.wat` (команды в его шапке);
- сам мастер ничего не печатает: каждая строка — ответ на команду, ошибки модулей лежат в журнале (`log`).

Пока нет: приостановки шага по `crab.yield` (шаг, исчерпавший лимит работы, завершается ошибкой «слишком
долго»), шины между модулями по USB (`topic`/`bus`), `id=` мастера,
безопасного режима после цикла перезагрузок, остального железа кроме цифровых пинов и часов. В `modcaps`
мастер честно сообщает только `flashmod,abi4,aot,rv32imc` — лист, которому нужно больше, редактор не зальёт.
`aot` вместе с именем процессора (`rv32imc` — ESP32-C3) говорит редактору, под что компилировать `.aot`;
без имени процессора редактор зальёт `.wasm`.

## Тесты на ПК

Из корня репозитория (так `.cargo/config.toml` этой папки не действует):

```text
cargo test --manifest-path firmware/master-rs/Cargo.toml
```

## Сборка под ESP32-C3

Один раз:

```text
rustup toolchain install nightly-2026-09-20 --component rust-src
cargo install ldproxy espflash
```

В `.deps/` (не в git):

- `.deps/wamr/` — исходники WAMR 2.4.5:
  `git clone --depth 1 -b WAMR-2.4.5 https://github.com/bytecodealliance/wasm-micro-runtime .deps/wamr`;
- `.deps/wamrc/wamrc.exe` — из `wamrc-2.4.5-x86_64-windows-2022.zip` с релиза WAMR на GitHub
  (или путь в переменной `CRAB_WAMRC`).

Сборка и заливка — из этой папки:

```text
cargo build --release
cargo run --release -- -p COM5
```

Первая сборка скачивает ESP-IDF v5.3.3 и его инструменты в `.embuild/` в корне репозитория (несколько ГБ, 10–30 минут).
Папка сборки — `.m/` в корне репозитория: esp-idf-sys на Windows не принимает путь сборки длиннее 88 символов,
поэтому имя короткое, а сам репозиторий должен лежать близко к корню диска.
`cargo run` заливает прошивку вместе с таблицей разделов `partitions.csv` (флеш в режиме QIO) и открывает монитор порта.

Скорость: Rust собирается с `opt-level = 3`, код ESP-IDF и WAMR — с `-O2` (`CONFIG_COMPILER_OPTIMIZATION_PERF`), флеш
работает в QIO. На C3 вызов `text` из модуля стал быстрее вдвое (29 → 13 мкс), шаг blink — в 5–6 раз (промахи кэша флеша). Если
плата с таким флешем не стартует (флеш без QIO), уберите `CONFIG_ESPTOOLPY_FLASHMODE_QIO` из `sdkconfig.defaults`
и `--flash-mode qio` из `.cargo/config.toml` и прошейте заново.

После запуска мастер печатает `master ready` и ждёт команд. Проверка руками — `tools/master.ps1`
(тот же протокол, что у редактора; умеет заливать и `.aot`, чего редактор пока не делает):

```text
tools\master.ps1 COM5 put blink <папка сборки>link.aot 'gpio_write,millis' then wait 1000 then list then info
```

`blink.wasm` и `blink.aot` собираются из `modules/blink.wat` в папку `out` сборки крейта
(`.m/riscv32imc-esp-espidf/release/build/crab-master-rs/*/out/`).

## Устройство

- `build.rs` — аргументы линковки ESP-IDF; `modules/*.wat` → `.wasm` и `.aot` (`wamrc --xip`, RV32IMC).
- `components/crab_wamr/` — список исходников и флаги WAMR (как в прототипе этапа 0) и `shim.c`:
  размер памяти из `crab.mem`, перевод указателей функций AOT с шины данных на шину команд для XIP,
  граница стека задачи.
- `src/protocol.rs`, `src/storage.rs`, `src/wamr.rs` — без железа, с тестами на ПК: разбор команд и потока
  порта (строки и куски образа), формат и учёт областей `crabmod` поверх трейта `Flash`, чтение `crab.mem`.
- `src/board/` — только для платы: `engine.rs` (WAMR через FFI), `devices.rs` (пины; 11–19 на C3
  модулям не даются: флеш и USB), `flash.rs` (раздел `crabmod`, отображённый в память), `usb.rs`
  (USB Serial/JTAG как байтовый порт), `mod.rs` (мастер: порт → шаг заливки → обход модулей).
- Рантайм и модули живут в одном потоке со стеком 32 КБ: WAMR сверяет стек с границей этого потока.
