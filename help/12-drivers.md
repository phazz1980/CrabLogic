# Драйверы железа на WASM

Свой датчик или устройство на шине можно подключить без пересборки мастер-прошивки: код блока — файл
`block.wasm` рядом с `block.toml`, написанный на любом языке, который собирается в WASM (Rust, C/C++, Zig…).
К железу драйвер обращается через функции мастера: GPIO, I²C, SPI, UART, 1-Wire. При сборке листа модулем
(`crablogic gen-wasm`, кнопка 📦) код драйвера вклеивается в модуль листа и заливается вместе с ним.

Драйверы работают **только с мастером на Rust** (возможность `bus`); мастер на C++ такой модуль не примет,
редактор скажет об этом до заливки. На железе пока не проверено.

Пример — `examples/wasm_driver`: датчик BMP280 по I²C на Rust (`rust/`) и на C (`c/`), готовый блок в
`library/bmp280/`, сборка — `build.ps1 rust` или `build.ps1 c`. При открытии примера блок BMP280 появляется на
вкладке «Блоки проекта» слева; «В библиотеку» там сохраняет его для других проектов.

## Блок с логикой без железа

Так же устроен и обычный пользовательский блок без шин (фильтр, счётчик моточасов): `block.toml` и
`block.wasm`, который зовёт только `crab.input/param/output/log`. Ограничения и сборка — те же, что ниже; в
симуляции на компьютере такой модуль выполняется по-настоящему, `sim` у выходов ему не нужен. Образцы на
Rust (логика, логика с памятью, драйвер BH1750) — `skills/crablogic-block/examples/`.

Блок, который едет с проектом-папкой, лежит в `<проект>/library/<тип>/`; в файле `.crab` он хранится внутри.
Проверка одного блока — `crablogic block check <папка блока>` (раздел «Командная строка» страницы «Сборка»).
`gen-wasm` складывает промежуточные файлы в `<проект>/.crab/` — её в git не кладут.

## Как устроен блок

- `block.toml` — входы, выходы, параметры, как у любого блока.
- `block.wasm` — экспорт `step(dt_ms: i32)` (каждый цикл листа), необязательный `init()` (один раз при
  запуске модуля), экспорт `__heap_base`.
- `param(i)` отдаёт параметр числом: `duration` — в миллисекундах, `pin` — номер GPIO, `bool` — 0 или 1.
- Выводы драйвера — параметры `type = "pin"`; у выводов общей шины — одинаковое имя `bus` (`"i2c-sda"`,
  `"i2c-scl"`, `"spi-sck"`, `"spi-mosi"`, `"spi-miso"`, `"onewire"`), тогда несколько блоков могут стоять на одной
  шине (у CS каждого устройства SPI вывод свой). Адрес I²C — целый параметр с `bus = "i2c-address"`, порт UART —
  целый параметр с `bus = "uart-port"` (1 или 2).
- Мастер даёт драйверу **только** эти выводы, адреса и порты: обращение к чужому выводу вернёт −1.
- У выходов можно задать `sim = значение` — его выход показывает в симуляции на компьютере (там драйвер не
  выполняется, шины нет). В редакторе блока это столбец «В симуляции».

## Функции для драйвера

Из модуля `crab` — как у модуля симуляции блока:

| Функция | Что делает |
| --- | --- |
| `input(i) -> f64` | вход номер `i` (по порядку `[[input]]`) |
| `param(i) -> f64` | параметр номер `i`; постоянные параметры видны уже в `init` |
| `output(i, value: f64)` | задать выход |
| `log(ptr, len)` | строка UTF-8 в журнал мастера |

Из модуля `bus` (все возвращают `i32`: 0 и больше — успех или значение, −1 — ресурс не заявлен,
−2 — ошибка шины или нет ответа, −3 — тайм-аут, −4 — неверные аргументы; функции обмена I²C, SPI, UART
и 1-Wire при успехе возвращают число переданных или принятых байт):

| Функция | Что делает |
| --- | --- |
| `gpio_mode(pin, mode)` | 0 вход, 1 выход, 2 вход с подтяжкой вверх, 3 — вниз, 4 открытый сток |
| `gpio_read(pin)`, `gpio_write(pin, level)` | уровень вывода |
| `i2c_open(sda, scl, hz)` | открыть шину I²C (одна на плату; `hz` 0 — 100 кГц) |
| `i2c_write(addr, ptr, len)`, `i2c_read(addr, ptr, len)` | передать или принять байты (до 256) |
| `i2c_write_read(addr, wptr, wlen, rptr, rlen)` | записать (обычно номер регистра) и прочитать |
| `uart_open(port, tx, rx, baud)` | открыть UART1/UART2 (8N1; на ESP32-C3 только 1) |
| `uart_write(port, ptr, len)`, `uart_read(port, ptr, cap)` | передать байты / прочитать, что пришло |
| `uart_available(port)` | сколько байт ждёт |
| `spi_open(sck, mosi, miso, hz)` | открыть SPI для драйверов (один на плату; `mosi`/`miso` −1 — не нужен; `hz` 0 — 1 МГц). На ESP32 это SPI3 (SPI2 у Ethernet W5500), на ESP32-C3 — SPI2: вместе с W5500 на C3 не работает |
| `spi_transfer(cs, ptr, len, mode)` | обмен `len` байт с устройством на выводе CS: отправляются байты из `ptr`, принятые кладутся туда же; `mode` 0–3 |
| `ow_reset(pin)` | сброс шины 1-Wire: 1 — устройство ответило, 0 — нет |
| `ow_write(pin, ptr, len)`, `ow_read(pin, ptr, len)` | байты по 1-Wire (нужен внешний резистор 4,7 кОм к питанию) |
| `ow_read_bit(pin)`, `ow_write_bit(pin, bit)` | по одному биту — для поиска адресов устройств на шине |
| `pulse_read(pin, start_us, ptr, count)` | прижать вывод к земле на `start_us` мкс (0 — не прижимать, до 20000), отпустить и замерить длины уровней: до `count` (1–128) чисел u16 в мкс по адресу `ptr`; уровень дольше 300 мкс заканчивает замер. Ответ — сколько уровней записано. Замер идёт аппаратным приёмником RMT с включёнными прерываниями (Wi-Fi не страдает); лист на это время ждёт. Каналов RMT на ESP32 хватает на 4 вывода, на ESP32-C3 — на 2; на следующих выводах замер идёт по-старому, программно с запретом прерываний. Для датчиков с ответом импульсами (DHT22) |
| `micros()` | микросекунды (с переполнением) |
| `delay_us(us)` | короткая пауза, не больше 100 мкс |

Указатели — адреса в памяти самого драйвера. Шаг драйвера не должен ждать: долгое ожидание (преобразование
датчика) делайте по шагам — запустили, через несколько шагов прочитали (так сделано в примере).

## Сборка модуля

- Rust: `#![no_std]` со своим `#[panic_handler]` (бесконечный цикл), `crate-type = ["cdylib"]`, `panic = "abort"`;
  состояние — `static mut`, ссылки на них брать через `core::ptr::addr_of_mut!`; флаги
  `-C target-cpu=mvp -C link-arg=-zstack-size=4096 -C link-arg=--export=__heap_base`.
- C: `clang --target=wasm32` (или `zig cc --target=wasm32-freestanding`) `-O2 -mcpu=mvp -nostdlib
  -Wl,--no-entry -Wl,-z,stack-size=4096 -Wl,--export=step -Wl,--export=init -Wl,--export=__heap_base`.

Память драйвера — его стек и данные (до `__heap_base`), не больше 32 КБ; она лежит внутри памяти модуля листа,
у каждого экземпляра блока своя. Нельзя: таблицы и косвенные вызовы (`dyn`, указатели на функции),
`memory.grow`, пассивные сегменты данных, импорты не из списка выше. Ошибка называет блок и причину.

Ошибка в драйвере (выход за свою память) может испортить данные других блоков листа, но не мастер: мастер
проверяет каждый адрес, который ему передают. Бесконечный цикл в драйвере не вешает другие листы.
