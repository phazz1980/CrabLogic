# Библиотека блоков

Каждый блок — папка `library/<тип>/`. Имя папки совпадает с `type` в `block.toml`.

## Встроенные и пользовательские блоки

- **Встроенные** — эта папка `library/`, они идут с программой. Менять их нельзя: в редакторе
  они открываются только для просмотра, а на их основе можно сделать свой блок.
- **Пользовательские** — папка `user_library/` рядом с `library/` (в корне репозитория), формат тот же.
  Их создаёт редактор блоков и ИИ-помощник (`create_block_type`). Пользовательский блок не может
  занять тип встроенного: такой блок пропускается с предупреждением.
  Каждый пользовательский блок лежит в **наборе** — верхней папке `user_library/<набор>/` с файлом
  `pack.toml` (`name`, `version`, `description`, `authors`, `contacts`, `license`). У блока своей версии
  нет: правка любого блока набора поднимает версию набора на 1. Новый блок по умолчанию попадает в
  набор «Мои блоки». Набор переносится одним файлом `.crabblocks` (блоки, их модули и
  примеры): в редакторе — окно пользовательской библиотеки, в командной строке — `crablogic block list`,
  `crablogic block export <набор> [файл]`, `crablogic block import <файл> [--replace]`.

Обе папки читают редактор, `crab` и MCP-сервер. В редакторе у библиотеки две вкладки —
«Встроенные» и «Пользовательские»; новый блок — «Библиотека → Новый блок…» или кнопка во вкладке
«Пользовательские», а правая кнопка на блоке даёт «Посмотреть / Изменить блок…», «Новый блок на
основе этого…» и для своих блоков «Удалить блок…». В окне редактора видно, как блок выглядит
на плате, и есть вкладка «Пробный прогон» модуля блока.

| Файл | Зачем |
| --- | --- |
| `block.toml` | название, группа, входы, выходы, параметры, описание |
| `block.wasm` | логика блока пользователя — модуль WASM (любой язык; интерфейс — `help/12-drivers.md` и папка `skills/`); у встроенных блоков его нет: код пишет Rust-тип из `crates/crab-blocks`. Блок на C++ (`esp32.cpp.tmpl`, `native.cpp`) больше не поддерживается: схема с ним не проходит проверку |
| `src/`, `build.cmd` | по желанию: исходник модуля (например Rust) и команда его сборки |

## block.toml

```toml
[block]
type = "timer_on"          # совпадает с именем папки
name = "Задержка включения" # как показывать в редакторе
group = "Время"            # папка в библиотеке редактора
description = "..."
symbol = "TON"             # короткое обозначение на блоке (по умолчанию — name)
memory = true              # блок хранит состояние между циклами
single = true              # в проекте может быть только один такой блок (Wi-Fi, NTP)
shared = "network"         # общий объект библиотеки (сеть, Modbus): на двухъядерных чипах
                           # блоки с меткой network сами уходят в фоновую задачу (ядро 0)
board = "my_board"         # блок принадлежит пользовательской плате (см. «Платы»): его видно
                           # и можно использовать только в проектах этой платы
expander = true            # блок можно поставить на вывод расширителя PCF вместо GPIO
                           # (см. «Расширители выводов»); нужен параметр type = "pin"

[[input]]
name = "in"
label = "Вход"             # необязательно: подпись на блоке и в свойствах, можно по-русски
type = "bool"              # bool | int | float | string; ещё number и same, у входа any
default = false            # необязательно: значение, если вход не подключён
description = "..."

[[output]]
name = "out"
type = "bool"

[[param]]
name = "time"
type = "duration"          # bool | int | float | string | duration | pin
default = "1s"             # без default параметр обязателен
min = 0                    # необязательные границы для чисел
max = 100                  # (у duration — в миллисекундах)
show = "named"             # подпись под блоком: named — «имя=значение» (по умолчанию),
                           # value — только значение, secret — значение под звёздочками
                           # кроме первого и последнего знака, hidden — не показывать
local = "ssid"             # значение хранится в программе (%APPDATA%\CrabLogic\local.toml)
                           # отдельно для каждого значения параметра ssid и не попадает
                           # в файл проекта; оба параметра строковые, нужен default
static = true              # значение нужно при генерации кода: параметр нельзя сделать входом
fixed = true               # значение всегда равно default и не показывается в свойствах:
                           # так плата закрепляет адрес и выводы своих блоков (см. «Платы»)
description = "..."

[[param.choice]]           # список значений: в свойствах — выпадающий список,
value = 0                  # под блоком — подпись варианта; другие значения
label = "Клиент"           # схема не примет (default должен быть в списке)

[[param]]
name = "pin"
type = "pin"
mode = "out"               # только для pin: io (по умолчанию) | in | out | pwm | adc | dac —
                           # какие выводы платы подходят (выход не на «только вход»,
                           # adc — только выводы с АЦП, dac — только с ЦАП)
shared = true              # только для pin: блоки этого типа могут делить вывод (шина 1-Wire)
bus = "i2c-sda"            # только для pin: блоки любых типов с одним именем шины могут делить вывод
min = -1                   # у pin с min < 0 значение -1 значит «не используется»
```

Выводы проверяются по плате проекта (ESP32, ESP32-C3, ESP32-S3; таблица в
`crab-core/src/pins.rs`): нет такого вывода, вывод флеш-памяти, не подходит по `mode` —
ошибка; UART0/USB — предупреждение. Один вывод у двух блоков (или у двух параметров
одного блока) — ошибка, кроме параметров с `shared` (блоки одного типа) и с одинаковым `bus`
(блоки любых типов: микросхемы на одной шине I²C). В окне свойств вывод выбирается
из списка, занятые выводы видны, но недоступны.

Имена типов, портов и параметров — буквы (можно русские), цифры и `_`, без пробелов и точек:
по ним блок связан в схеме (`from = "блок.порт"`) и в модуле блока.
Чтобы на блоке и в окне свойств было название с пробелами, задайте `label` — у входа, выхода и параметра. Имена общие на весь блок
(входы, выходы и параметры не могут называться одинаково). Имена `id` и `type` заняты.

Неявное приведение типов только одно: `int` → `float`. Вход с `type = "any"`
принимает выход любого типа (и константу любого вида). У выхода типа `any` не бывает.
Тип `number` — любое число: вход берёт `int` или `float`, выход `number` — `int`, только
если все входы `number` целые. Тип `same` — для переключателей: входы `same` берут любой
тип, но все поданные на них сигналы одного типа (`int` с `float` дают `float`); выход `same`
получает этот тип. Значение по умолчанию
чужого типа на неподключённом входе `same` заменяется нулём нужного типа.
Тип `string` — текст (IP-адрес, сообщение, имя); с числами он
не смешивается: числа в строку и обратно переводят блоки группы «Строки». В онлайн-отладке
строки видны (до 64 байт), но не форсируются.

### Условия `when`

У входа, выхода и параметра может быть условие `when`: порт или параметр есть у
блока, только пока условие выполняется. Условие — выражение Jinja;
параметры блока в нём — просто имена, `duration` — в миллисекундах:

```toml
[[input]]
name = "val"
type = "int"
when = 'source == "input"'   # вход «время» появляется, только если выбран источник «вход»

[[param]]
name = "time"
type = "duration"
when = 'source == "const"'   # обязателен, только пока виден
```

- Отключённого порта нет на схеме: связь с ним — ошибка `crablogic check`,
  неподключённый отключённый вход ошибкой не считается.
- Отключённый параметр редактор не показывает, и он не обязателен; если у него
  есть значение, блок его всё равно получает.
- В условии можно упоминать только параметры блока, и параметр не может зависеть
  от самого себя — это проверяется при загрузке библиотеки.

Вход без `default` обязательно должен быть подключён, иначе `crablogic check` выдаст ошибку.
У выходов `default` не бывает: до первого цикла они равны false / 0.

`memory = true` разрешает обратные связи: цикл в схеме допустим, только если
проходит через блок с памятью. Связь, замыкающая цикл на такой блок, получает
значение с прошлого цикла программы; цикл без блока с памятью — ошибка `crablogic check`.

## Логика блока

Встроенные блоки считает Rust-код программы (`crates/crab-blocks`: симуляция и инструкции WASM
для модуля листа). Блок пользователя приносит свой `block.wasm`: модуль читает входы и
параметры и пишет выходы, а драйверы железа ходят через шины мастера. Как собрать такой
модуль — `help/12-drivers.md`, `help/10-block-editor.md` и папка `skills/crablogic-block/`.

## Блоки на UART

Скорость, формат и выводы аппаратных UART задаются один раз в настройках платы
(`[[uart]]` в `project.toml`), а блок указывает, какой UART берёт и как:

```toml
[block.uart]
param = "port"         # int-параметр блока с номером порта: -1 — USB, 0, 1, 2 — UART
access = "write"       # exclusive | write | read | config
```

- `exclusive` — порт настраивает библиотека блока (Modbus RTU); больше никто его не использует;
- `write` — блок только отправляет; таких блоков на одном порту сколько угодно;
- `read` — блок принимает; читатель у порта один;
- `config` — блок сам задаёт настройки порта своими параметрами `speed`, `format`,
  `rx`, `tx`, `de`, `rx_buffer` (так устроен «Настройки UART»); порт тогда не
  настраивается в «Настройках МК», а владельцем блок не считается.

Порты с `write` и `read` открывает сам генератор модуля в начале работы (размер буфера,
скорость с форматом и выводами, режим RS-485 при выводе DE).
Номер `-1` — это USB (`Serial`): у него нет настроек, скорость 115200, блоки могут
писать и читать (не `exclusive`). Аппаратные UART — 0, 1, 2, какие
есть у платы: ESP32 — 1 и 2 (её UART0 — это USB-мост), ESP32-C3 — 0 и 1, ESP32-S3 — 0, 1, 2.
Проверка схемы ругается на ненастроенный UART, на UART, которого нет у платы,
на двух владельцев одного порта и на выводы UART, занятые блоками.

## Расширители выводов

Цифровой вход или выход может стоять на выводе микросхемы PCF8574, PCF8574A или PCF8575
(`[[expander]]` в `logic.toml`) вместо GPIO. Блок разрешает это флагом `expander = true`
в `[block]`; у него должен быть параметр `pin` (первый такой параметр блока). В схеме
у блока на расширителе стоит `expander = "<id>"`, а `pin` означает номер вывода микросхемы
(P0 — 0), а не GPIO; проверка схемы такой `pin` с GPIO не сверяет.

Шину (`I²C`), опрос и запись выводов расширителя ведёт мастер; блок на расширителе
читает и пишет только состояние выводов. Блоки на фоновых листах так же читают и пишут только
слова, обмен с чипом идёт в основном цикле.

## Переменные

Переменные объявляются в `logic.toml` и используются на платах встроенными
блоками `var_get` (чтение, выход `out`) и `var_set` (запись, вход `in`):

```toml
[[var]]
name = "setpoint"
type = "float"        # bool, int, float, double, String и другие типы переменных
init = 22.0           # значение после включения, по умолчанию false / 0

[[block]]
id = "setpoint_r"
type = "var_get"
var = "setpoint"
```

Читать переменную можно сколько угодно раз и на любой плате, записывать — в одном
месте. В пределах цикла запись выполняется раньше чтения; если чтение и запись
образуют петлю, чтение берёт значение с прошлого цикла. Переменная, которую никто
не записывает, — уставка с начальным значением. Пример — `examples/tags`.

## Платы

Плата, которой нет в списке, — папка `user_library/boards/<id>/` (рядом с `library/`):
`board.toml`, `docs.md` с описанием и `images/` с картинками схем и фотографий. Её пишет
окно «Библиотека → Новая плата…», но файлы можно править и руками: платы читаются при каждой
загрузке библиотеки, перекомпиляция не нужна. `boards` — не раздел библиотеки блоков.
`<id>` — строчные латинские буквы, цифры и `_`; он совпадает с именем папки, это же
значение `board.model` в `project.toml`, а id встроенной платы занять нельзя.

```toml
[board]
id = "kincony_kc868_a6"     # совпадает с именем папки
name = "Kincony KC868-A6"   # как плата называется в списках
chip = "esp32"              # esp32 | esp32c3 | esp32s3: от чипа зависят UART, АЦП и запретные выводы
fqbn = "esp32:esp32:esp32"  # идентификатор платы (по нему выбирается образ мастера)
version = 1                 # необязательно: увеличивайте при изменении выводов и периферии

[[pin]]                     # вывод, выведенный наружу; без [[pin]] доступны все выводы чипа
gpio = 36
name = "A1"                 # как напечатано на плате: в списках «A1 · GPIO36»
note = "Аналоговый вход"    # пояснение для окна платы
busy = "занят шиной I²C"    # необязательно: чем занят на плате; блок на нём получит предупреждение
functions = ["din", "adc"]  # необязательно: что вывод умеет на плате — din | dout | pwm | adc | dac.
                            # Не шире, чем умеет чип (ЦАП — только GPIO25/26 у ESP32); без поля —
                            # всё, что умеет чип. Блок видит вывод, только если функция подходит его `mode`

[[device]]                  # распаянная периферия: готовый блок без ввода адресов
id = "relays"               # тип блока — <id платы>_relays
kind = "pcf8574_out"        # встроенный блок, копия которого делается (pcf8574_out | pcf8574_in)
name = "Реле"               # в библиотеке — «Kincony KC868-A6: Реле»
description = "Реле K1–K6"
channels = ["K1", "K2", "K3", "K4", "K5", "K6"]  # подписи портов p0, p1…; портов столько же
address = 36                # дальше — значения параметров встроенного блока:
sda = 4                     # они закреплены (fixed) и в свойствах не показываются
scl = 15
inverted = true
```

Выводы расширителя, который распаян на плате, описывает отдельная таблица `[[expander_pin]]`
(микросхема, адрес и шина берутся из `[[device]]` с `kind = "pcf8574_out"` / `"pcf8574_in"`):

```toml
[[expander_pin]]
device = "relays"           # id из [[device]]
pin = 0                     # вывод микросхемы: P0
name = "K1"                 # как напечатано на плате: в списках «P0 · K1»
note = "Реле 1"
functions = ["dout"]        # только din | dout; без поля — оба
```

В проекте в свойствах цифрового входа или выхода выводы описанных расширителей идут в том же списке,
что и GPIO, под заголовком «Плата: <имя устройства>»: выбор строки ставит блок на расширитель проекта с
тем же чипом, адресом и шиной, а если такого нет, создаёт новый с параметрами платы. В списке только
описанные в `[[expander_pin]]` выводы; не подходящие блоку по функции серые. `crablogic check` ругается на вывод, которого плата
не выводит, или без нужной функции. Без `[[expander_pin]]` расширитель работает как обычный
(любой вывод микросхемы).

Устройство — настроенная копия встроенного блока (`crab-core/src/devices.rs`): тот же код
блока, тип `<id платы>_<id устройства>`, поле `board` равно id платы, `single = true` (один
такой блок в проекте), параметры из `[[device]]` закреплены, а `count` берётся из числа
каналов. Блок чужой платы проверка схемы отклоняет, а предупреждения о занятых выводах
шины у собственных блоков платы подавляются. Описание платы проверяет `BoardDef::validate`:
id и совпадение с папкой, чип, FQBN, повторы устройств и выводов GPIO, выводы вне чипа;
неизвестный встроенный блок `kind` — ошибка загрузки. Сломанная плата пропускается с
сообщением, остальные работают; `crablogic board check <папка>` проверяет одну плату и называет ошибку.
Инструкция для ИИ-помощников — `skills/crablogic-board/`.

Проект `.crab` хранит копию платы в `user_boards/<id>/` и разворачивает её, если на этом
компьютере такой платы нет (проект-папка может нести такую же папку `user_boards/`).
Отдельный файл `.crabboard` — ZIP папки платы (`crab-core/src/boardfile.rs`). Пример —
`examples/kc868_a6_relays`.

| Сеть | Modbus RTU и TCP, Wi-Fi, Ethernet, `ntp` |
| Веб-интерфейс | страница управления на ESP32: блок «Веб-интерфейс» и виджеты (кнопка, переключатель, ползунок, ввод, индикатор, значение, шкала, текст, заголовок) |

Каждый блок встречается хотя бы в одном примере из `examples/`; это проверяет
тест `every_block_has_an_example`, а то, что каждый блок и каждый пример собирается модулем
листа, — тест `crates/crab-codegen/tests/library_modules.rs`.
