# Ethernet

Проводная сеть: модуль WizNet W5500 (подходят W5100 и W5200) по шине SPI или микросхема LAN8720
по шине RMII (только классический ESP32). Чип выбирается параметром «Чип»; по умолчанию W5500.

## W5500 (SPI)

Выводы SPI назначаются параметрами `sck`, `miso`, `mosi` и `cs`; по умолчанию для ESP32 DevKit
SCK — 18, MISO — 19, MOSI — 23, CS — 5. Выход `ready` — есть ли связь, выход `address` (параметр
«Выход IP») — IP-адрес строкой, пока связи нет, строка пустая.

Блок один на проект. У «Modbus TCP Slave» выберите `net = "ethernet"`, чтобы
он работал через этот блок.

Пример: `examples/modbus_ethernet`.

## LAN8720 (RMII)

LAN8720 подключается к встроенному Ethernet (EMAC) классического ESP32. У ESP32-C3, S2 и S3 EMAC нет —
проверка схемы ответит ошибкой «блок чужой платы». MAC-адрес заводской, из ESP32 (параметр `mac` не нужен).

Выводы данных RMII у ESP32 постоянные и заняты всегда: 19 (TXD0), 21 (TX_EN), 22 (TXD1), 25 (RXD0),
26 (RXD1), 27 (CRS_DV). Остальное задаёт параметр «Плата»:

| Плата | Адрес PHY | MDC | MDIO | Питание PHY | Такт 50 МГц |
|---|---|---|---|---|---|
| ESP32 + модуль LAN8720 (по умолчанию) | 1 | 23 | 18 | нет | вход GPIO0 |
| WT32-ETH01 | 1 | 23 | 18 | 16 | вход GPIO0 |
| Olimex ESP32-POE | 0 | 23 | 18 | 12 | выход GPIO17 |
| Свои выводы | `phy_addr` | `mdc` | `mdio` | `power_pin` (−1 — нет) | `clock` |

Все эти выводы общая проверка считает занятыми: другой блок на них поставить нельзя.

**Внимание: такт на GPIO0.** У большинства отдельных модулей LAN8720 генератор 50 МГц подаёт такт на GPIO0,
а GPIO0 — загрузочный вывод. Если генератор работает с момента включения, ESP32 может стартовать в режиме
загрузки прошивки и не запустить программу. Надёжная схема — вывод «Питание PHY»: прошивка включает
им генератор (или PHY) уже после старта. Для «Своих выводов» с тактом на GPIO0 без вывода питания проверка
схемы выдаёт предупреждение; для готовых плат из списка — нет (плата такая, какая есть). Если плата не стартует по питанию — заведите
вывод питания генератора на свободный GPIO и выберите «Свои выводы».

Пример: `examples/eth_lan8720` (LAN8720 + Modbus TCP Slave). Не проверено на железе.

## Веб-страница

Блок всегда поднимает веб-сервер на порту 80 (отдельной настройки нет): на нём работают страницы
блока «Веб-интерфейс» (`web_ui`), в том числе страница «Система» — IP, MAC, аптайм, дата сборки
(у Wi-Fi ещё уровень сигнала). У Wi-Fi и Ethernet в одном проекте свои серверы, каждый на своём интерфейсе.

## В модуле WASM

Блок работает и в модуле (`crablogic gen-wasm`): интерфейсом владеет мастер-прошивка, модуль один раз
передаёт чип, выводы, MAC, DHCP и адреса, а на каждом шаге читает `ready` и `address`. Выводы SPI и MAC
мастер берёт при первом запуске интерфейса: их смена требует перезагрузки платы, а DHCP и адреса
применяются на лету. Wi-Fi и Ethernet можно использовать одновременно, у каждого свой адрес; время
по кабелю берёт `ntp` с `net = "ethernet"`. Веб-страница в модуле пока не работает
(страница работает через мастер, см. «Веб-интерфейс»), параметры из переменных не поддержаны. Пример —
`examples/net_eth_wasm`. LAN8720 в модуле работает только с мастером на Rust для классического ESP32;
мастер на C3 пишет в журнал, что LAN8720 нужен ESP32 с EMAC. Не проверено на железе.

## Период опроса сети

Параметр «Период опроса сети, мс» (по умолчанию 5) ограничивает, как часто обслуживаются сеть, MQTT,
веб-страница: не чаще одного раза за период. Отклик запаздывает не больше чем на период.
0 — обслуживать в каждом цикле.
