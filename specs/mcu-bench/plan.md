# Замеры производительности — план

## Стенды

`examples/bench/` — проекты-стенды, собранные генератором (не вручную), чтобы размер задавался числом:
`crab-cli` строит их в памяти из шаблонов `logic` / `float` / `timers` / `text` / `calls_<вид>` / `empty` с N
блоками. Сеть: стенд `net` = лист float на 100 блоков + Wi-Fi + MQTT-публикация раз в 100 мс; настройки Wi-Fi
и MQTT подставляются в служебные переменные проекта из `bench/secrets.toml` (`[wifi] ssid, password`,
`[mqtt] host, port, user, password`). Файл и папка `bench/*.toml`, кроме `bench/secrets.example.toml`, — в
`.gitignore`.

## Команда (`crab-cli`, модуль `bench.rs`)

Для каждого стенда: собрать модули (`gen-wasm`, AOT или интерпретатор — переключатель режима листа),
залить (замер времени), подождать 10 с, снять три раза `list` с паузой 2 с (шаг: `us=`, `steps=`, `mem=`,
`free/largest/min`), взять средние. Время от перезагрузки — команда мастера `restart` и время до первого
`list` со `steps>0`. Результат — `BenchReport` (serde) → `.toml` и `.md`. `--compare` читает два `.toml`.
Протокол платы — существующий (`crab-build::mcu_module`, `crab-debug`), прошивку мастера не меняем; если
какого-то числа в `list` нет — графа «—».

## Риски

- Разброс из-за Wi-Fi: сетевой стенд отдельно, остальные — с выключенной сетью.
- 500 блоков могут не влезть на C3 (память) — тогда строка «не влезло» с причиной, прогон идёт дальше.
- Пароли: `BenchReport` не содержит настроек сети; проверка теста — в выводе нет строки из `secrets`.
