# Вставка блока в связь: план

## Затронутые места

- `crates/crab-core/src/link_insert.rs` (новый): `Project::insert_into_link(lib, block, to) -> Result<Insert, EditError>`
  работает с блоком, который уже стоит в схеме (новый блок сначала добавляет `add_block`, а при отказе всё
  откатывается: `Doc::edit` восстанавливает снимок при `Err`). `to` — вход приёмника, он же ключ связи.
  `Insert` = `Spliced` (вставка), `Replaced` (у блока нет подходящего входа), `Branch` (нет подходящего выхода).
  Новые ошибки `EditError`: `NoLink`, `InsertOwnLink`, `InsertNoPort`.
- `crates/crab-core/src/lib.rs`: `mod link_insert; pub use link_insert::Insert;`
- `crates/crab-ai/src/lib.rs`: команда `insert_block_in_link` (`type` или `block`, `to`, позиция) — один шаг правки.
- `crates/crab-editor/src/canvas/`: при перетаскивании (из библиотеки и блока листа) ищем ближайшую связь, чья
  ломаная пересекает прямоугольник блока под указателем; подсвечиваем её; при отпускании — `add_block` +
  `insert_into_link` одним `doc.edit` (или `insert_into_link` для блока листа); итог (ответвление, замена, отказ) — в строку состояния.
- `help/02-editor.md`, `help/07-ai.md`, `docs`-страницы; запись в `help/09-news.md`.

## Правила выбора портов

Вход: первый по порядку в `block.toml`, у которого нет связи, константы и привязки и тип которого принимает
источник (`SignalType::can_feed`). Выход: первый, чей тип принимает приёмник. Сами соединения делает
`Project::connect` (проверка типов, адаптация блоков переменных, снятие константы с входа приёмника).

## Риски

- Блок переменной меняет роль при первом соединении (`adapt_var_block`): вставка идёт через `connect`, так что правило то же.
- Подсветка зависит от геометрии канваса (ломаные связей в экранных координатах) — проверяется глазами, поэтому
  ядро принимает уже выбранную связь, а выбор ближайшей — отдельная чистая функция с тестом.
