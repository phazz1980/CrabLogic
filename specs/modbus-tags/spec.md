# Теги Modbus slave: создание по адресу и типу

## Цель
Теги Modbus создаются в папке «Сеть → Modbus» левой панели кнопкой «+»: имя, таблица, тип, адрес.
Размеры таблиц регистров считаются по тегам, а не задаются числом в блоке.

## Решения (обсуждение 18.11.2026)
- Пока только **slave** (таблица тегов slave). Master — позже.
- В строке тега есть направление: «из схемы» (значение пишет схема, master читает) и
  «в схему» (значение пишет master, схема читает).
- Таблицы: Holding, Input, Coil, Discrete. Типы: int, float, bool. Coil и Discrete — только bool,
  Holding и Input — int или float.
- Занятость адресов: int — 1 регистр, float — 2, bool — один бит своей таблицы. Следующий свободный адрес
  подставляется автоматически (после float по адресу 0 — адрес 2). Пересечения запрещены и подсвечиваются,
  проверка схемы их тоже находит.
- Размер каждой таблицы **вычисляется** по тегам (максимальный адрес + размер); числа
  «holding / input / coils / discrete» в блоке «Modbus TCP/RTU Slave» не нужны.
- Порядок слов float — необязательная настройка тега (по умолчанию как сейчас: старшее слово первым, ABCD).
- Старые блоки «Чтение/Запись Modbus» совместимость не держим: они нигде не использовались.

## Критерии готовности
- «+» в папке Modbus создаёт тег с адресом по умолчанию = следующий свободный; float занимает два адреса.
- Пересечение адресов в одной таблице видно в панели и находится `crablogic check`.
- Размеры таблиц на плате соответствуют тегам; тест на ПК и пример `examples/`.
- Справка (`help/`) и `docs.md` блоков обновлены.

## Вне задачи
Master-таблица тегов, Unit ID на тег, ASCII, шлюзы RTU↔TCP.
