# Задачи: внутренняя шина и Sparkplug B

Шаг 1 — шина
- [x] 1. Манифест: поле `topics` (имя, вид state/event, max_len, queue); разбор и проверка в `crab-sim`. (юнит-тест разбора)
- [x] 2. `crab-sim`: топик-состояние хранит последнее значение и отдаёт его при `subscribe`. (тест `tests/mcu.rs`)
- [x] 3. `crab-sim`: очередь события — drop-oldest и счётчик потерь. (тест переполнения)
- [x] 4. Тест «заменили публикатора — подписчик не перезапускался, увидел новое значение и сохранённое».
- [x] 5. Мастер-прошивка (`specs/wasm-on-mcu/proto/master/master.ino`): счётная очередь до 16 (по умолчанию 8), drop-oldest + `lost`,
  топики state/event с `maxLen` и `refused`, последнее значение новому подписчику, команды `topic`, `queue`, `bus`.
  Проверено на ESP32-C3 (COM5): модуль публикует 1,2,3 за шаг — для state читатель видит `3` один раз, для event с очередью 2 — `2`,`3`, `lost=1` (как в `crab-sim`).
  Не сделано: топики объявляются командами в рантайме и не хранятся во flash (манифест пока не едет с `put`); горячая замена публикатора и поздний подписчик на плате не проверены; на C3 два модуля по 64 КБ памяти не помещаются в кучу (проверка шла одним модулем, подписанным на себя).
- [x] 6. Потери шины в отладке мастера: `list` печатает `qlost=<n>` на модуль, `crab-debug` суммирует в `Stats.bus_lost` (тест `lost_bus_messages_of_all_modules_are_summed`), редактор показывает строку в диагностике. Образ состояния (`debug-image`) не менялся: у мастера свой канал `list`. Проверено на ESP32-C3: `list` даёт `qlost=1` после сценария с очередью 2 (`#include <Preferences.h>` вынесен из блока `CRAB_WEB`, иначе мастер не собирался).
- [x] 7. Справка и раздел архитектуры (шина, лимиты, манифест).

- [ ] 10. Подключение к mqtt-модулю, will = `NDEATH` (решения в `plan.md`):
