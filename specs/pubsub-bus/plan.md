# План: внутренняя шина и Sparkplug B

Шаг 1 (шина) и шаг 2 (Sparkplug) независимы; Sparkplug опирается на карту смещений из `specs/debug-image`.

## Шаг 1. Доработка шины
- Хост (`crab-sim/src/mcu.rs`, затем мастер-прошивка): таблица топиков с типом «состояние» / «событие» и
  максимальной длиной; тип задаётся манифестом модуля (`module.toml`, список `topics`), без манифеста — «событие».
- «Состояние»: хост хранит последнее значение; `subscribe` сразу доставляет его вызовом `on_message`;
  при горячей замене публикатора значение сохраняется.
- «Событие»: очередь на подписчика, размер из манифеста (по умолчанию 8), при переполнении выбрасывается
  самое старое; счётчик потерь на подписчика доступен отладке (`crab-debug`, образ состояния).
- Прототип мастера (`master.ino`): кольцо 4 → настраиваемое, drop-oldest, счётчик потерь, топик ≤ 23 / данные ≤ 64
  заменить на значения из манифеста с проверкой при сборке.
- `crab-codegen`: тип топика и размер — из блоков-публикаторов (проверка «подписка без публикатора» — предупреждение).
- Теги не трогаем.

## Шаг 2. Sparkplug B
- Новый крейт `crab-sparkplug` (без ссылок на GUI и arduino-cli): сборка protobuf-пейлоада (`Payload`, `Metric`
  с именем, типом, алиасом), `bdSeq`, `NBIRTH`/`DBIRTH`/`NDATA`/`DDATA`/`NDEATH`; метрики строятся из карты смещений.
- Транспорт — существующий mqtt-блок/модуль (`specs/wasm-io/mqtt*.md`); пароли и брокер в модуле, не в мастере.
- Проверка: эталонные байты пейлоада, совместимые с Eclipse Tahu (сверка с публичными примерами).

## Риски
- ОЗУ ESP32: очередь × топики × модули; ограничить манифестом и проверять при сборке.
- Состояние при замене модуля: два публикатора одного топика — определить правило (последний пишет).
- Sparkplug протобуф вручную без внешних крейтов — объём небольшой, но нужны эталоны для тестов.

## Решения по Sparkplug B (07.11.2026)
- Will-сообщение: правим клиент `libs/FLProg_Network` (`setWill`), запись в `libs/README.md` («Локальные правки»).
- Кодирование пейлоада во время работы — в мастер-прошивке на C++ (зеркало `crab-sparkplug`, проверка тестами на те же байты).
  Модуль передаёт мастеру группу, узел, список метрик (имя, тип) и значения; мастер сам ведёт `bdSeq`/`seq`, birth/data/death.
- Шаги: (a) patch клиента — сделано; (b) блоки `sparkplug_node` и `sparkplug_metric` в библиотеке и их WASM-вывод через
  новые операции мастера; (c) C++ в `master.ino`: protobuf, `NBIRTH`/`NDATA`/`NDEATH`, will перед connect, повтор birth при
  переподключении; (d) тест на плате и на брокере (Mosquitto + Sparkplug-клиент); (e) справка.
