# Проверка LoRa E220 на железе (одна плата, без второго узла)

Для задач 9 и 10 из `tasks.md`. Нужно: плата ESP32 с Rust-мастером, модуль E220-400T22D с антенной, сборка CrabLogic из `dist\CrabLogic.zip` (версия 2.0.1 с LoRa).

## Подключение (как проверялось в плане)
| Модуль E220 | Плата ESP32 |
| --- | --- |
| RXD | GPIO22 (TX платы) |
| TXD | GPIO19 (RX платы) |
| M0 | GPIO23 |
| M1 | GPIO18 |
| AUX | GPIO5 |
| VCC, GND | 3,3 В (или 5 В по паспорту модуля), GND |

Антенна обязательна. Модуль на этом шаге **один**: обмена нет, проверяется настройка модема и расход платы.

## Проект для проверки
Папка `lora_bench` с двумя файлами.

`project.toml`:
```toml
[project]
name = "lora_bench"
description = "Проверка LoRa: ведомый, один модем"

[board]
fqbn = "esp32:esp32:esp32"
```

`logic.toml`:
```toml
[[block]]
id = "modem"
type = "lora_e220"
role = 1
node = 0
channel = 18
uart = 2
tx = 22
rx = 19
m0 = 23
m1 = 18
aux = 5

[[block]]
id = "centre"
type = "lora_centre"
modem = "modem"
n_cmd = 2
t_cmd0 = 0
t_cmd1 = 1
n_ans = 2
t_ans0 = 1
t_ans1 = 0

[[link]]
from = "centre.cmd0b"
to   = "centre.ans1b"
```
(`m1 = -1` значит, что M1 соединён с M0: один пин на оба. `tx` и `rx` — выводы платы: TX платы идёт на RXD модуля.
После каждой заливки модуля сбрасывайте плату кнопкой EN: см. `bugs.md`, «UART драйвера остаётся занятым». Проверено 18.11.2026: `modem.ready = 1`.)

## Шаги (из папки распакованной программы, `<порт>` — COM платы)
1. `crablogic check lora_bench` — ожидается «ошибок нет».
2. `crablogic gen-wasm lora_bench --watch --upload --port <порт>` — модуль заливается вместо текущего (мастер не трогается; если на плате не Rust-мастер, сначала `crablogic flash-master`).
3. `crablogic monitor lora_bench --port <порт>` — смотреть строку значений.

## Что ожидается
- В течение нескольких секунд после заливки `modem.ready = 1`. Это значит: модуль отозвался на чтение регистров, настройка прошла (при первом запуске драйвер **запишет регистры во флеш модуля**: канал 18, 2,4 кбит/с, мощность 10 дБм, адрес — это нормально, прежние настройки модуля заменятся).
- `modem.rssi` — 0 или случайное, `modem.bad` — 0 (второго узла нет).
- `centre.linked = 0` (центр не слышен), `centre.cmd0b`, `cmd1i` — 0.
- Если `ready` остаётся 0: проверить, что TX и RX не перепутаны (TX платы — на RXD модуля), M0/M1 соединены между собой и с GPIO23, AUX на GPIO5, питание и общий GND; модуль заводской (9600 8N1). Через минуту-две драйвер сам повторяет попытку.

## Что записать (для задачи 9)
Окно «Диагностика» (⏱) редактора в режиме отладки, или поля `list` из `monitor`: время шага листа (последнее, среднее, максимум), свободная куча мастера, размер модуля. Сравнить с `bench/history.md` (плата ESP32): прирост времени шага и памяти от модема. Одна строка в `bench/history.md`: дата, плата, «LoRa: модем без обмена», цифры.

## Для проверки через ИИ на месте
Вставьте в Claude Code на том компьютере (рабочая папка — распакованный CrabLogic или репозиторий):

> Выполни `specs/lora-e220/hw-test.md` на плате ESP32 на порту <порт>: создай проект `lora_bench` из файла, проверь схему, залей модуль с `--watch`, 20 секунд смотри `monitor` и скажи, стало ли `modem.ready = 1` и за сколько секунд. Потом залей без `--watch` и сними время шага листа, свободную кучу и размер модуля (через `crablogic monitor` или `list`). Ничего не меняй в мастере. Если `ready` не стал 1, перечисли, что проверить в подключении, ничего не перепаивая сам. Итог — таблица цифр и строка для `bench/history.md`.

## Два узла (задача 10, потом)
Центр: `examples/lora_star` (в нём пины ESP32 по умолчанию: TX 17, RX 16, M0 25, M1 27, AUX 33 — поправить под свою плату), ведомый: `examples/lora_slave` на второй плате. Одинаковые канал, скорость в эфире и ключ; проверить: `centre.online` / `linked` становятся `1`, команда с кнопки доходит до ведомого за ≤ 3 с, потеря связи (выключить ведомого) за `offline` (10 с) даёт `online = 0` и нули в ответах, возврат связи сам.
