# Управление значениями в отладке и симуляции — план

Крейты: только `crab-editor` (ядро и протокол не меняются: форсировка и ручные значения уже есть —
`debugview::value_menu`, `simview::port_menu`, команды `crab-debug`).

1. **Блокировка схемы.** Одно место: `EditorApp::schema_locked()` = `debug.is_some() || sim.is_some()`.
   Проверять в `canvas/` (перетаскивание блоков, протяжка и удаление связей, вставка из панелей, меню правки),
   в командах правки и отмены (`editlog.rs`), в дереве слева (добавить/удалить/переименовать), в окнах свойств.
   Главная защита — на входе применения правки (команда отвергается, сообщение в строке состояния), серые кнопки — вторично.
   Подсказка на листе — в `canvas/mod.rs`.
2. **Щелчок по значению.** На виджете значения (`debugview::value_label`, ручной вход стенда) и на порту:
   ЛКМ/ПКМ по `bool` → `true`/`false` (в отладке — команда форсировки, в симуляции — ручное значение).
   В этих режимах меню правой кнопки на bool-портах не открывается; для чисел — окошко.
3. **Окошко числа.** Небольшой `egui::Area` у значения; виджет `panels::stepper`: ЛКМ — `+шаг`, ПКМ — `−шаг`,
   удержание — повтор с ускорением (пауза 400 мс, затем 8→30 раз/с по времени `ctx.input`), `request_repaint`, пока зажато;
   ввод с клавиатуры. В плату — не чаще опроса (5–7 раз/с), последнее значение не теряется.
4. **Сброс форсировки.** Кнопка у значения и в `values_window`; «Снять все» в панели отладки. Снятие уже есть в `value_menu` —
   вынести в общую функцию. В симуляции — «снять ручное значение».
5. **Справка и документы:** `help/` (отладка, симуляция), `help/09-news.md`, словари, `Архитектура и план.md`.

Риски: egui не даёт «удержание ПКМ» готовым событием — `ctx.input(|i| i.pointer.button_down(Secondary))` над виджетом;
места правки схемы разбросаны — собрать поиском мутаций `app.doc`; массивы (спека arrays-structs) — элемент меняется тем же окошком.
