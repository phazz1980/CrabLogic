# Полный переход на Rust — спецификация

Статус: согласовано 12.11.2026, ответы на все вопросы — в разделе «Вопросы». План — `plan.md`, задачи — `tasks.md`.

## Цель

Редактор работает только с мастер-прошивкой на Rust: схема собирается в WASM-модули листов и заливается
в мастер. Путь «скетч Arduino C++ → arduino-cli → прошивка» и мастер на C++ уходят из программы вместе с
меню и вкладками, которые к ним относятся. Пользователю не нужны arduino-cli, ядро ESP32 и библиотеки
Arduino.

## Что есть сейчас (12.11.2026)

> Список «не умеет» ниже частично устарел: `MODCAPS` Rust-мастера уже покрывает все `MASTER_CAPS`, а DS18B20/DHT22
> уже драйверы `block.wasm`. Настоящие пробелы — по замеру, этап A в `plan.md`.

- Два пути: «Собрать/Залить» (скетч C++ через arduino-cli) и «Залить модули» (WASM в мастер на C++ или Rust).
- Мастер на C++ (Arduino) — основной, умеет всё. Мастер на Rust (C3, ESP32) — опытный: GPIO, время, шины
  драйверов, Wi-Fi, NTP, MQTT, Sparkplug B, Ethernet W5500 и LAN8720, AOT.
- Rust-мастер **не умеет** (по `MASTER_CAPS`): `math`, `retain`/`retain_text` (сохранение во флеш),
  `tag_text`, `uart_format`/`uart_console` (UART, Modbus), `pcf_expander` (PCF8574), `on_fault`, `native`
  (нативные части C++: DS18B20, DHT22 и др.), ШИМ/АЦП — проверить; веб-интерфейс — проверить.
- В редакторе C++ видно: меню «Код C++», «Собрать (F5)», «Залить мастер-прошивку» (сборка через arduino-cli),
  установка arduino-cli и ядра, «Папка библиотеки Arduino»; в редакторе блока — вкладки «Код ESP32»
  (`esp32.cpp.tmpl`), «Код C++ для платы» (`native.cpp`, «Собрать мастер для проверки»), «Библиотека
  Arduino (мастер)», «Создать по шаблону»; условие `when` «код попадёт в скетч».

## Сценарии

1. Новый пользователь ставит программу, подключает ESP32/C3, жмёт «Залить мастер» — мастер на Rust
   прошивается без arduino-cli и без интернета (прошивка мастера лежит в дистрибутиве).
2. Собирает схему из встроенных блоков (вход, логика, таймеры, датчики, MQTT…) и жмёт «Залить» — листы
   уходят модулями, отладка работает как сейчас.
3. Пишет свой блок: логика — в редакторе блока без C++; железо — драйвер `block.wasm` (Rust/C/…).
4. Открывает старый проект — схема открывается; блоки, которые в Rust-пути не работают, отмечены
   понятной ошибкой проверки.
5. Просит любую ИИ-модель (Claude, другую модель в Claude Code, Codex, Cursor и т. п.) «сделай блок, который…».
   Модель находит в репозитории папку `skills/` с инструкцией по пользовательским блокам и по ней, без
   чтения кода редактора, создаёт рабочий блок: `block.toml`, логику или драйвер `block.wasm`, `docs.md`,
   пример — и сама проверяет результат командами `crablogic`.

## Папка skills: инструкция для ИИ по пользовательским блокам

Пишет Claude (основная сессия) в конце перехода, когда формат блока на Rust-пути устоялся. Цель — чтобы
более слабая или чужая модель делала блоки без ошибок с первого раза. Состав:

- `skills/crablogic-block/SKILL.md` — точка входа: frontmatter `name` и `description` с **триггерами**
  (рус./англ.: «создай блок», «новый блок», «пользовательский блок», «драйвер датчика», `block.toml`,
  `block.wasm`, «new block», «custom block», «sensor driver»); пошаговый порядок работы; что запрещено
  (C++, `esp32.cpp.tmpl`, `native.cpp`, правка `crates/`); ссылки на справочники ниже.
- `reference/` — короткие справочники: все поля `block.toml` (порты, типы, параметры, состояние, `when`);
  логика в редакторе блока; драйвер `block.wasm` (API шин мастера, сборка из Rust и C, размеры, AOT);
  правила `docs.md` и переводов; коды ошибок проверки с типовыми исправлениями.
- `examples/` — три эталонных блока с пояснениями: чистая логика, логика с параметрами и памятью,
  драйвер датчика на шине (по образцу BMP280).
- `checklist.md` — что проверить перед сдачей (команды, ожидаемый вывод, пример в `examples/`).
- **Хуки** `skills/crablogic-block/hooks/` (`.ps1` и `.sh`) + подключение в `.claude/settings.json`:
  после записи `library/**/block.toml`, `docs.md` или исходников драйвера — автоматическая проверка блока
  (`crablogic block check <папка>` и `gen-wasm` его примера), ошибки возвращаются модели; перед завершением
  (`Stop`) — полный чек-лист. Те же скрипты вызываются вручную моделями без поддержки хуков.
- `AGENTS.md` в корне и правило Cursor `.cursor/rules/crablogic-block.mdc` — указатели на
  `skills/crablogic-block/SKILL.md` для не-Claude агентов.
- Новая команда CLI `crablogic block check <папка>` — проверка одного блока с понятными ошибками
  (её вызывают хуки и чек-лист).
- **Дистрибутив**: `skills/`, `AGENTS.md`, `.claude/settings.json` с хуками и `.cursor/rules/` кладутся
  рядом с папкой пользовательских блоков, вместе с `crablogic` CLI, — пользователь открывает эту папку
  в Claude Code или Cursor без репозитория. Пути в хуках — относительно этой папки.

Дополнительно (по просьбе 12.11.2026): `skills/crablogic-board/` — инструкция по добавлению своей платы
(пользовательского контроллера): SKILL.md с триггерами, справочники `board-toml.md` и `chips.md`, образец
платы с проектом, чек-лист; проверка — новая команда `crablogic board check <папка>`. `skills/README.md` —
оглавление папки, `AGENTS.md` в корне указывает на него.

Правило актуальности: меняется формат блока или платы, API шин или команды CLI — в том же шаге правится `skills/`
(как и справка).

## Критерии готовности

- В редакторе нет пунктов меню, кнопок и вкладок про C++/скетч/arduino-cli/`native.cpp`.
- Мастер на Rust прошивается из редактора без arduino-cli (проверено на C3 COM5 и ESP32 COM10).
- Все встроенные блоки либо работают модулем на Rust-мастере, либо убраны/помечены (по ответу на вопрос 2).
- `crablogic` (CLI): нет `gen`/`build`/`upload` для скетча; есть `check`, `gen-wasm`, заливка модулей и мастера.
- Справка, README, `Архитектура и план.md`, CLAUDE.md не упоминают C++-путь как действующий.
- Тесты, clippy, примеры `examples/` проходят `gen-wasm`.
- Есть `skills/crablogic-block/` (SKILL.md с триггерами, reference, examples, checklist, хуки), `AGENTS.md`
  и `.cursor/rules/`; хук срабатывает на правку `block.toml` и возвращает ошибки `crablogic block check`.
- То же лежит в дистрибутиве рядом с папкой пользовательских блоков и работает из неё без репозитория.
- Проверка инструкции: модель попроще (Sonnet/Haiku) в чистой сессии, получив только задание и `skills/`,
  делает 3 блока (логика, логика с памятью, драйвер датчика), и все проходят проверку и `gen-wasm`
  без правок человеком; найденные пробелы дописаны в `skills/`.

## Вне задачи

AVR и STM32 (отложены); Wi-Fi-транспорт отладки; каталог блоков.

## Вопросы

1. **Порядок.** Сначала дописать в Rust-мастер всё, чего не хватает (math, flash-сохранение, UART/Modbus,
   PCF8574, on_fault, DS18B20, DHT22, ШИМ/АЦП, веб-интерфейс), и только потом убрать C++ — или убрать
   C++ сразу, а неподдержанные блоки временно скрыть?
   **Ответ (12.11.2026):** сначала дописать в Rust-мастер всё недостающее, потом убрать C++.
2. **Блоки без поддержки в Rust-мастере** на время перехода: скрыть из библиотеки, показывать с пометкой
   «не работает на Rust-мастере», или удалить?
   **Ответ:** показывать с пометкой «не работает на Rust-мастере» и ошибкой проверки схемы.
3. **DS18B20, DHT22 и прочие датчики с нативной частью**: переписать как драйверы `block.wasm` (поверх
   1-Wire/шин мастера, как BMP280) — или встроить их в мастер на Rust нативно?
   **Ответ:** драйверы `block.wasm` поверх шин мастера (как BMP280).
4. **Прошивка мастера**: класть в дистрибутив готовые образы мастера (C3, ESP32) и прошивать через
   `espflash`, встроенный в редактор как библиотека (без отдельного exe), — так?
   **Ответ:** да — готовые образы в дистрибутиве, `espflash` встроен как библиотека.
5. **Код C++ в репозитории** (`firmware/master` C++, генератор Arduino в `crab-codegen`, `crab-build`
   с arduino-cli, `esp32.cpp.tmpl` блоков, `libs/`): удалить из репозитория (останется в истории git) или
   оставить в репозитории, но выключить из сборки и редактора?
   **Ответ:** удалить из репозитория (остаётся в истории git).
6. **Пользовательские блоки с `esp32.cpp.tmpl`/`native.cpp`**: при открытии — ошибка проверки «блок на C++
   больше не поддерживается», или пробовать собирать их логику иначе?
   **Ответ:** ошибка проверки «блок на C++ больше не поддерживается» со ссылкой на `skills/`.
7. **Режим «Скетч» в старых проектах** (настройки сборки, библиотеки Arduino в проекте): молча
   игнорировать или показать одно сообщение при открытии?
   **Ответ:** одно сообщение при открытии; при сохранении эти настройки убираются.
8. **Версия**: это выпуск 2.0.0?
   **Ответ:** да, выпуск 2.0.0.
9. **Где лежит `skills/`**: только в репозитории — или ещё и в дистрибутиве?
   **Ответ (12.11.2026):** и в дистрибутиве, рядом с папкой пользовательских блоков.
10. **Какие агенты поддерживаем** кроме Claude Code: хватит `AGENTS.md` или нужны правила Cursor?
    **Ответ:** да, кроме `AGENTS.md` нужны и правила Cursor (`.cursor/rules`).
11. **Команда проверки одного блока** для хука: добавить в CLI `crablogic block check <папка>` (быстрее,
    понятные ошибки) — или хватит `check`/`gen-wasm` на примере блока?
    **Ответ:** да, добавить `crablogic block check <папка>`.
