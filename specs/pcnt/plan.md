# План: быстрый счётчик, частота, энкодер

## Блоки (id не пересекаются с `encoder` = «Шифратор»)

| id | Имя | Входы | Выходы | Параметры |
|---|---|---|---|---|
| `fast_counter` | Быстрый счётчик | `reset` (bool) | `count` (int), `ok` | `pin`, `dir_pin` (−1 — только вверх; 1 на выводе — вверх, 0 — вниз), `edge` (фронт/спад/оба), `filter` (мкс, 0 — выкл.) |
| `frequency` | Частота | — | `hz` (float), `count` (int), `ok` | `pin`, `edge`, `window` (длительность, по умолч. 1 с), `filter` |
| `quad_encoder` | Энкодер | `reset` | `pos` (int), `dir` (int −1/0/1), `ok` | `pin_a`, `pin_b`, `mode` (x1/x2/x4), `filter` |

Выводы — параметры `pin` с `mode = "in"` (класс «вход» в порядке блоков, проверка занятости — как у других).
Счёт 32 бита со знаком, при переполнении заворачивается (`i32` wrapping), это пишется в `docs.md`.

## Драйверы и шина мастера

Драйверы — `block.wasm` (`drivers/fast_counter`, `frequency`, `quad_encoder`), как DHT22: решение «драйверы
поверх шин мастера». В `crab.bus` добавляются операции (`crab-kernel/src/abi.rs` `bus_op`, разбор и
проверка захватов — `crab-kernel/src/bus.rs`):

- `COUNT_OPEN(pin_a, pin_b, mode, filter_us)` → номер счётчика 0..7 или код ошибки; выводы должны быть захвачены
  (`CLAIM` gpio). `mode`: 0 фронт, 1 спад, 2 оба (с `pin_b` — направление), 3/4/5 — квадратура x1/x2/x4.
- `COUNT_READ(n)` → накопленный счёт (i32). `COUNT_CLEAR(n)`.
- `COUNT_PERIOD(n)` → для частоты: число фронтов и время между первым и последним фронтом за окно
  (см. вопрос в спеке), пишется в память модуля (8 байт).
- `COUNT_KIND()` → 1 аппаратный PCNT, 2 программный (прерывания GPIO).

Счётчик освобождается вместе с модулем (как каналы RMT в `pulse.rs`). Версия ABI не меняется: новые
операции; старый мастер отвечает «неизвестная операция», драйвер выдаёт `ok = false`.

## Мастер (`firmware/master-rs/src/board/count.rs`, новый)

- **ESP32/S3:** драйвер ESP-IDF `pcnt` (`driver/pulse_cnt.h`): блок PCNT на счётчик, пределы ±32767,
  `accum_count` — переполнение 16 бит копится в прерывании, чтение `pcnt_unit_get_count` (короткая
  критическая секция, без ожидания). Фильтр — `pcnt_unit_set_glitch_filter` (до ~12 мкс на 80 МГц).
  Квадратура — два канала одного блока (таблица действий по фронтам A и уровню B). ESP32 — 8 блоков, S3 — 4.
- **C3:** прерывание GPIO по фронтам →
  `AtomicI32` (для энкодера — таблица переходов по состоянию A/B). Предел частоты замеряется и пишется в
  предупреждение проверки и справку.
- Шаг читает счёт одним вызовом, без блокировок мастера (`Spin` не нужен: таблица счётчиков меняется
  только при `COUNT_OPEN`/освобождении, вне шага — в загрузке модуля).

## ПК

- `crab-core`: проверка — на C3 предупреждение «программный счёт, до N кГц»; больше 8 (S3 — 4) блоков на
  плате — ошибка. Число берётся из семейства чипа (`boards.rs`).
- `crab-sim`: стенд — для вывода счётчика вводится частота (Гц, со знаком для энкодера); выходы считаются
  моделью в `schema.rs` (`count += hz·dt`, `hz`, `pos`, `dir`), сброс работает.
- `crab-codegen`: тесты сборки модулей трёх блоков (`library_modules.rs`), хост-тесты драйверов
  (декодирование, окно частоты) на ПК.
- Справка: страница блоков (раздел «Счётчики»), `docs.md` трёх блоков, новости; примеры
  `examples/flow_meter`, `examples/encoder_knob`.

## Риски

- Фильтр PCNT короткий (≤ 12,7 мкс): для дребезга механических энкодеров/контактов — отдельный блок
  «Антидребезг» не годится на высоких частотах; в справке — RC-фильтр на входе.
- Программный счёт на C3 нагружает ядро шага (одно ядро): предел частоты ставим консервативно.
- Проверка на железе: ШИМ платы (LEDC) → провод → вход той же платы; энкодер — два канала ШИМ со сдвигом
  фаз (LEDC `hpoint`) или ручка.
