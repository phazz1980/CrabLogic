# Поиск плат в локальной сети

## Цель
Не вводить IP руками: кнопка «Найти платы» в редакторе и команда `crablogic find` показывают платы
CrabLogic в локальной сети; выбранная подставляется в `[board] host` для отладки и заливки по сети.

## Решения (обсуждение 18.11.2026)
- Запрос — UDP-широковещание на фиксированный порт (отдельный от порта команд 4040). Плата отвечает одним
  пакетом; сама ничего не рассылает.
- Отвечают **все** платы с адресом Wi-Fi или Ethernet; платы без ключа для сети помечаются «ключа нет»
  (так удобнее первая настройка: ключ записывают по USB командой `netkey`).
- В ответе: IP, имя проекта и id платы (по MAC, различает одинаковые платы), чип, версия мастера, короткий
  хеш проекта, есть ли ключ. Без секретов; вход по-прежнему по ключу.
- Имя и id платы общие для USB и сети (то же имя видно и при подключении по USB).
- ПК рассылает запрос **по каждому сетевому адаптеру** (широковещательный адрес его подсети), чтобы поиск
  работал и при включённом VPN.
- mDNS (`crablogic-<id>.local`) не делаем.

## Критерии готовности
- `crablogic find` печатает найденные платы (IP, имя, id, чип, версия, хеш, ключ есть/нет); при пустом
  результате подсказывает про брандмауэр и подсети.
- В окне «По сети…» кнопка «Найти платы» показывает список, выбор подставляет адрес в `[board] host`.
- Формат запроса и ответа разбирается тестами на ПК; мусор, чужие пакеты и слишком длинные пакеты отвергаются.
- Плата отвечает не чаще заданного темпа (защита от шквала запросов), без аллокаций в рабочем цикле и без
  влияния на скан; ответ не содержит секретов.
- Проверено на ESP32 и C3 в одной сети.
- Справка (`help/05-build.md` или раздел про сеть) и «Что нового» обновлены; ограничения сказаны прямо:
  широковещание не проходит через другую подсеть и VLAN, брандмауэр Windows может блокировать ответы.

## Вне задачи
mDNS, поиск через другие подсети, поиск по USB (порты уже видны), управление платой из списка.
