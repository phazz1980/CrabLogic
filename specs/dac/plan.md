# План: аналоговый выход (ЦАП)

## Как устроено сейчас

«ШИМ-выход» — встроенный блок: генератор модулей (`crab-codegen/src/wasm/hardware.rs`) зовёт импорт ядра
`pwm_write(pin, value)`. Номер вывода несёт биты: 0–7 вывод, 8 подтяжка, 9–10 `on_fault`. Ядро
(`crab-kernel/src/host.rs`) берёт аренду вывода (`lease::PinUse`, `Fault`), при выгрузке или падении
модуля `Hal::safe` ставит безопасное состояние, сторож скана (`board/watchdog.rs`) держит его копию в
`SAFE` и выставляет из прерывания. Вид вывода «ЦАП» (`PinMode::Dac`, GPIO25/26 ESP32) в `crab-core/pins.rs`
уже есть, общая проверка параметра `pin` с `mode = "dac"` даёт ошибку на чужом выводе и на плате без ЦАП.

## Решение

Тем же путём, что «ШИМ-выход», без драйвера `block.wasm`: это вывод платы, а не шина.

1. **ABI** (`crab-kernel/abi.rs`): новый импорт `dac_write(pin, code)` в конец таблицы (id не сдвигаются),
   признак мастера `dac` в `MODCAPS` только у ESP32. Модуль с ЦАП на мастере без признака не грузится
   (как остальные признаки).
2. **Аренда**: `PinUse::Dac`; `Fault` получает вариант `Value(u8)`. Биты `on_fault` = 3 — «заданное
   значение», код в битах 16–23 номера вывода. Для ЦАП: «0 В» = `Low`, «держать» = `Hold`,
   «значение» = `Value(code)`. `High` для ЦАП не выдаётся.
3. **Генератор**: блок `analog_out` — вход `in` (int, ограничение 0…255 через `clamp_int`), вход `en`
   по `write_enable`, параметры `pin` (`mode = "dac"`), `on_fault` (0 В / держать / значение),
   `fault_value` (0…255, `when` на `on_fault = 2`). Вход назван `in`, как у остальных выходов
   (в спеке было `value`).
4. **Мастер** (`board/analog.rs`): `dac_write` — при первом обращении `dac_oneshot_new_channel`
   (хендл в статическом массиве на 2 канала), дальше запись кода одной функцией без блокировок шага
   (у драйвера — короткая критическая секция). `forget_output` и отказ от LEDC на этом выводе.
   `Hal::safe` для `PinUse::Dac`: код 0 или `Value`. Сторож: `SAFE` расширяется до кода с значением
   (`AtomicU16`), из прерывания ЦАП пишется прямо в регистр (`RTC_IO_PAD_DACn_REG`, поле `PDACn_DAC`),
   без вызовов драйвера.
5. **Проверка схемы**: общая проверка вывода; текст ошибки на C3 и на чужом выводе проверить тестом и
   при необходимости уточнить («ЦАП только на GPIO25 и GPIO26 у ESP32»).
6. **Симуляция**: поведение в `crab-blocks/hardware.rs`, `dac_out` в заглушке `crab-sim/mcu.rs`,
   показ напряжения (код·3,3/255) в окне симуляции и на блоке.
7. **Справка**: `library/analog_out/docs.md` (выход слаботочный, нужен повторитель; не для аварийных
   функций), `help/` — страница блоков ввода-вывода, новости; пример `examples/dac_ramp`.

## Риски

- `dac_oneshot` в IDF 5 при создании канала отключает вывод от GPIO-матрицы: перед этим вывод не должен
  быть занят LEDC/GPIO-выходом (проверка схемы не даст двух блоков на одном выводе; при замене модуля
  с ШИМ на ЦАП — освободить LEDC).
- Регистр ЦАП для сторожа — проверить адрес по TRM ESP32 и замером (выход прерывания → 0 В).
- Замер ±50 мВ — мультиметром пользователя; без него — АЦП той же платы (GPIO25 → вход АЦП перемычкой
  нельзя без проводов; петли через IO_MUX у ЦАП нет), так что критерий 1 — только с пользователем.
