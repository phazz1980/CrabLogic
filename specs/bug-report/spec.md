# Отчёт об ошибке одной кнопкой

## Цель

Тестер (не программист) одной кнопкой сохраняет ZIP со всем, что нужно разработчику, чтобы понять и повторить
ошибку, и сам отправляет файл (почтой, в мессенджер). Без сервера, без командной строки, без утечки паролей.

## Ответы пользователя (14.11.2026)

1. Отчёт — просто ZIP-файл, тестер отправляет его сам. Сервер и GitHub — не сейчас.
2. Проект кладётся в отчёт только по галочке, пароли и ключи в нём замаскированы.
3. Под core dump платы отдаём 64 КБ флеша (раздел `coredump` уже есть в `partitions.csv`, в ESP-IDF
   не включён — места модулям не убавится).
4. Тестеры — не программисты: всё одной кнопкой.

## Сценарии

1. «Справка → Сообщить об ошибке…»: окно с полем «Что делали и что пошло не так», галочками «Приложить
   проект (пароли скрыты)» и «Данные платы» (если плата подключена), кнопка «Сохранить отчёт…». Готовый
   файл показывается в проводнике.
2. Редактор упал: при следующем запуске — «В прошлый раз программа завершилась с ошибкой. Сохранить отчёт?»;
   текст ошибки и место в коде уже в отчёте.
3. Плата перезапустилась после сбоя (паника, сторож): при подключении редактор пишет об этом в журнале, а отчёт
   забирает с платы дамп сбоя, причину перезапуска и журнал мастера.
4. Разработчик открывает ZIP: `report.md` читается глазами, дамп платы расшифровывается командой
   `crablogic report decode <zip>` по прошивке той же версии.

## Что в отчёте

- `report.md` — описание тестера, версия программы и мастера, ОС, время, плата и порт, последние действия.
- `editor.log` — журнал редактора (кольцевой файл на диске, последние сообщения, ошибки сборки и заливки).
- `panic.txt` — текст и стек паники редактора, если была.
- `board.txt` — ответы платы `list`, `info`, `log`, причина и число перезапусков.
- `coredump.elf` — дамп сбоя платы, если есть.
- `project.crab` — по галочке; значения секретных полей (пароли Wi-Fi, MQTT, ключи, токены) заменены на `***`.

## Критерии готовности

1. Отчёт без платы сохраняется одной кнопкой за 5 с; с платой — за 15 с; сбой чтения платы не мешает
   сохранить остальное (в отчёте — что не удалось).
2. Ни одно значение секретного поля проекта не попадает в ZIP: тест на проекте с Wi-Fi, MQTT и Modbus.
3. Паника редактора ловится, при следующем запуске предлагается отчёт (тест паники в отладочной сборке).
4. Искусственный сбой мастера на ESP32 и ESP32-C3 даёт дамп; он попадает в отчёт и расшифровывается в стек
   с именами функций.
5. Журнал редактора не больше 1 МБ на диске, старые записи вытесняются.
6. Чтение дампа и журнала с платы не задерживает шаг (идёт между шагами, порциями, с CRC).
7. Справка: страница «Сообщить об ошибке», новости.

## Вне задачи

Отправка на сервер или в GitHub, телеметрия, автообновление, снимок экрана (позже — по галочке).
