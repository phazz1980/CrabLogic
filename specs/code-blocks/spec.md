# Блоки на коде: C++ «как Arduino» и Rust

Продолжение `specs/wasm-blocks/` (ABI `block.wasm`), `specs/template-sim/` (zig собирает C++ в WASM) и
`specs/wasm-drivers/` (шины мастера). Обсуждение 11–12.11.2026: свой блок пользователь пишет кодом, основной язык —
C++ в стиле Arduino, второй — Rust с крейтом-помощником. Оба дают один и тот же `block.wasm`, поэтому блок работает
в симуляции, в пробном прогоне и в модуле на плате без пересборки мастера. Скриптовые интерпретаторы (Lua, Rhai,
MicroPython) на плате не используем; ST (МЭК 61131-3) отложен.

## Цель

Автор пишет блок в окне редактора блока на привычном C++ (`setup()`, `loop()`, `millis()`, `digitalRead`, `Wire`…),
сохраняет — через секунду блок работает в симуляции и попадает в модуль листа. Служебной части ABI (`crab.input`,
номера портов, `panic_handler`) автор не видит. Для Rust то же даёт крейт `crab` с макросом.

## Сценарии

1. Создаю блок «Тревога с задержкой»: объявляю в коде входы, параметры и выходы, пишу `loop()` на `millis()`.
   Сохраняю — порты появляются в `block.toml`, блок виден в библиотеке, «Пробный прогон» работает.
2. Ошибка в коде — сборка не проходит, в окне блока список ошибок со строками; частые ошибки — по-русски.
3. Драйвер датчика на I²C пишу через `Wire.beginTransmission/write/requestFrom`, выводы и адрес — параметрами
   блока; мастер пускает только к ним (правила `wasm-drivers`).
4. zig не установлен — при создании первого блока на коде программа предлагает скачать его одной кнопкой
   в папку инструментов; без zig остальная программа работает как прежде.
5. Пишу на Rust: подключаю крейт `crab`, описываю блок структурой с `#[input]`/`#[output]`/`#[param]`, собираю
   `cargo build` — получаю тот же `block.wasm`, что и из C++.
6. Блок с ошибкой (бесконечный цикл, выход за массив) не роняет ни редактор, ни мастер: шаг обрывается лимитом
   топлива или ловушкой WASM, в журнале — блок и причина.

## Критерии готовности (проверяемые)

- `crab.h`: описанное в справке подмножество Arduino API (время, GPIO, `Wire`, `Serial1/2`, `SPI`,
  `OneWire`, `Serial.print` → журнал, фиксированный `String`), поверх `crab.*` и `bus` без изменения мастера.
  АЦП и ШИМ (`analogRead/analogWrite`) — следующим шагом: им нужны новые функции шины в мастере.
- Порты из объявлений в коде попадают в `block.toml` (тест на разбор; порядок портов стабилен).
- Примеры в `examples/`: тот же блок на C++ и на Rust (через `crab`) дают одинаковые выходы на одном сценарии
  входов (тест в `crab-sim`, нужен `CRAB_ZIG`); один драйвер I²C на C++.
- Окно блока: редактор кода, сборка при сохранении, ошибки по строкам; скачивание zig по кнопке.
- Модуль листа с таким блоком собирается `gen-wasm` и заливается; на плате — когда будет проверено
  (иначе «не проверено на железе»).
- Справка: новая страница «Блоки на коде», правки `help/10-block-editor.md`, `help/12-drivers.md`, новости; переводы.

## Вне задачи

- Библиотеки Arduino из интернета как есть (работают только «чистые», без регистров и прерываний).
- Прерывания, DMA, микросекундные протоколы (остаются у мастера).
- Свой компилятор (ST или C-подобный язык), отладчик по строкам кода, публикация крейта `crab` на crates.io.

## Решено (12.11.2026)

1. **`delay()` запрещён.** `loop()` — один шаг скана; `delay()`/`delayMicroseconds()` дают ошибку сборки
   с подсказкой «используйте millis()». Приостановка блока (`crab.yield`, 3.1б wasm-kernel) остаётся отложенной.
2. **zig скачивается по кнопке** при создании первого блока на коде, в папку инструментов программы; в сборку
   программы не входит. Путь можно задать и вручную (настройка `zig_path`, как у template-sim).
3. **Порты объявляются в коде** (`CRAB_INPUT/CRAB_PARAM/CRAB_OUTPUT` в C++, поля с атрибутами в Rust);
   `block.toml` редактор заполняет сам, название, группу и описание правят в окне блока.
4. **Шаблоны:** новые блоки — только на коде; существующие `esp32.cpp.tmpl` переводятся кнопкой «Перевести»
   по мере надобности.
5. **Исходник** (решение за мной): C++ — один файл `block.cpp` в папке блока рядом с `block.wasm`, редактор его
   собирает. Rust — подпапка `rust/` (`Cargo.toml` + `src/lib.rs`, как в `examples/wasm_block/rust`), собирает автор
   через `cargo`, редактор только подхватывает `block.wasm`. Исходник хранится и копируется вместе с блоком;
   `block.wasm` из `block.cpp` помечается как сгенерированный (правило template-sim: чужой не перезаписываем).
