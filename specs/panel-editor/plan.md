# Ручная правка листов щита: план

## Главное изменение: сцена вместо потока операций

Сейчас генераторы (`power.rs`, `control.rs`) пишут рисунок прямо в `Canvas` (список `Op`), у символа
нет ни имени, ни выводов. Для правки мышью нужны: кто нарисован, где его выводы, какие провода к ним
идут. Поэтому листы собираются как **сцена**, а `Op` получаются из неё:

- `SymbolItem { device, view, origin, ops, ports }`: символ устройства (силовая часть, катушка,
  клеммы платы и т. д.) в координатах листа, его рисунок относительно `origin`, выводы
  (`Port { name, pos, dir }`).
- `WireItem { wire key, from, to, class, route }`: провод между выводами, путь — ломаная по
  правилам ортогональной трассировки (как `route` на листе FBD, с одним изгибом).
- `StaticItem`: рамка, заголовки, шины, подписи — не двигаются.

Редактор рисует сцену сам (интерактивно: порты, подсветка, перетаскивание), PDF строится из той же
сцены; расхождения «на экране не так, как в PDF» быть не должно.

## Раскладка поверх автогенерации

- Файл `panel-layout.toml` (в архиве рядом с `layout.toml`; старые проекты без него читаются):
  `[symbols."вид:устройство"] dx, dy` — смещение от автоположения в единицах (1 u = 0,25 мм, кратно
  сетке 0,5 M); `[wires."ключ провода"] bend` — положение среднего сегмента.
- Смещение, а не абсолютное положение: автораскладка может сдвинуться при добавлении устройств, а
  ручная правка остаётся относительно неё. Ключи удалённых устройств вычищаются при сохранении.
- Генераторы принимают `&PanelLayout` и применяют смещения **до** вычисления зон и ссылок, поэтому
  перекрёстные ссылки следуют за ручным положением.

## Перепайка

Операции в `crab-core` (рядом с `Panel`, без рисования): `reconnect_power(device, new_parent)`
(меняет `load` у старого и нового питающего: у питающего `load` один), `rebind(device, tag)`,
`unbind(device)`. Правила как у проверки щита (`check/panel.rs`), отказы с причиной по-русски.
Редактор подсвечивает допустимые выводы при перетаскивании конца провода.

## Редактор

`crab-editor/src/panelview.rs`: вместо картинки из `Op` — холст сцены с теми же жестами, что в
`canvas/` (`geometry::route`, `rounded`, `near_polyline`, подсветка ближайшего; общий код выносится,
где можно). Правки идут в историю: смещения и путь — `doc.edit_panel`, перепайка — тоже. Справа
свойства устройства остаются.

## Риски

- Провода силовой цепи сейчас — шины и вертикали под фиксированную сетку колонок; при свободном
  перемещении символа трассировка должна оставаться читаемой. Первая версия: ортогональный маршрут с
  одним изгибом и ручная правка изгиба; полноценная автотрассировка не делается.
- Рефакторинг генераторов широкий; защита — существующие тесты (`power_sheet.rs`, `control_sheet.rs`,
  `format.rs`) зелёные на каждом шаге; первые шаги рисунок не меняют (операции до и после равны).
- Вид на экране проверяется только глазами; чистые части (трассировка, смещения, перепайка) — тестами.
