# План: фаза 1 — модули по сети (OTA мастера — фаза 2, когда будет плата 8/16 МБ)

## Как устроено сейчас

- ПК: заливка модулей — `crab-build/src/mcu_module.rs` (`upload_module`, `upload_image`, `delete_module`,
  `wait_for_master_info`), всё обобщено над `Read + Write` — годится и `TcpStream`. Порт выбирают
  `crab-cli` (`gen-wasm --upload -p`) и редактор (`crab-build::SerialPort`).
- Плата: поток `crab-io` (`board/io.rs`) читает USB, разборщик `Input` превращает строки и куски образа в
  события для шага (`TO_SCAN`); ответы шага идут в очередь `usb::OUT`, `crab-io` пишет их в порт.
- Сеть поднимают модули (блоки `wifi`, `ethernet`; настройки едут с модулями). Без сетевого модуля сети нет.

## Решение

1. **Сервер команд на плате** (`board/netcmd.rs`, новый): фоновая задача `crab-netcmd` (ядро 0 на ESP32),
   стартует, когда готов Wi-Fi или Ethernet; TCP-порт **4040**, один клиент за раз (второй — отказ «busy»).
   После входа байты клиента идут в тот же разборщик (`io::with_input`) — команды, заливка кусками, `info`,
   `list`, `del`, `log` работают как по USB. Ответы: пока клиент подключён, `crab-io` отдаёт копию очереди
   ответов и в TCP (USB тоже получает — второй собеседник по USB не нужен одновременно, пишем в справке).
   Обрыв связи посреди заливки — как обрыв USB: незавершённый образ не переключается, работает прежний.
2. **Пароль** (обязателен): ключ = SHA-256(«crablogic» ‖ пароль проекта) хранится в NVS платы (`crab_net/key`).
   Ставится только по USB командой `netkey <64 hex>` (физический доступ), снимается `netkey -`. Без ключа сервер
   не слушает порт. Вход: плата шлёт `auth <nonce 16 байт hex>`, клиент отвечает `auth <HMAC-SHA256(ключ, nonce)>`
   (mbedtls из ESP-IDF); неверно — пауза 1 с, после 5 неудач подряд — порт закрыт на 60 с. До входа — только
   приветствие. Пароль и ключ по сети не передаются.
3. **ПК:** `crab-build` — тип «адрес платы» (`Target::Serial(port) | Target::Tcp(host)`), подключение с входом
   (`net_connect(host, password)`), команда установки ключа по USB (`set_net_key`). `crab-cli`: `--host <адрес>`
   у `gen-wasm --upload`, `info`/`monitor`-подобных команд, где есть порт; `crablogic netkey -p COMx` ставит ключ из
   пароля проекта. Редактор: в выборе платы — «по сети: адрес» (адрес запоминается в настройках проекта
   `[board] host`, не в `logic.toml`), при заливке модулей по USB предлагается записать ключ.
4. **Проект:** пароль — тот же `[project] password` (без пароля в проекте заливка по сети недоступна, редактор
   так и говорит).
5. **Справка:** `05-build.md` (заливка по сети, ключ, порт 4040, один собеседник), `15-reliability.md` (обрыв
   связи), новости. Блок `wifi`/`ethernet` `docs.md` — что через них можно заливать модули.

## Риски

- Сетевой модуль с ошибкой в настройках сети отрезает плату от сети — вернуть только по USB (в справке).
- Память: сервер — стек ~4 КБ + сокет lwIP; на C3 с Wi-Fi куча тесная (запас 16 КБ из `specs/safety-audit`).
- Копия ответов в TCP не должна задерживать `crab-io` (запись в сокет с тайм-аутом, переполнение — обрыв клиента).
- Брандмауэр Windows спрашивает только при входящих; у нас ПК — клиент, не мешает.

# План: фаза 1б — отладка, `monitor`, `upload-wasm` по сети

## Как устроено сейчас

- Отладка с Rust-мастером — `crab-debug::MasterSession` (текстовый опрос `list`, `info`, `out <модуль> <n>`, уставки
  и форсировка командами) поверх `transport::Connector` (сейчас только `serial`). Сессия сама переподключается
  через `Connector` и показывает «плата молчит». Карту модулей (`ModuleMap`: CRC, слоты наблюдаемых выходов) строит
  редактор в `debugview.rs`.
- **Найдено:** `crablogic monitor` и живые значения ИИ (`crab-ai/folder.rs`) до сих пор используют старую двоичную
  `Session` (её понимала только удалённая прошивка на C++) — с Rust-мастером они не показывают значений.
- Вход по сети (`net_key`, `auth_answer`, `connect`) — в `crab-build/net_link.rs`; `crab-debug` от `crab-build` не
  зависит.

## Решение

1. **`crab-debug::transport::tcp(host, password) -> Connector`** (признак `net`, зависимости `sha2`, `hmac`): TCP,
   вход вызов-ответ, тайм-аут чтения 50 мс → «нет данных», запись с тем же сроком, что у USB. Сюда же переезжают
   `net_key`, `auth_answer`, `login` из `net_link.rs`; `crab-build` начинает зависеть от `crab-debug` и берёт их
   оттуда (одна реализация входа). Ошибка входа (неверный пароль, занято, нет ключа) — понятный текст в статусе.
2. **Карта модулей для отладки** — из `debugview.rs` в `crab-build` (`debug_modules(program, table, work_dir)`):
   общая для редактора, `monitor` и ИИ.
3. **Редактор:** отладка берёт связь из выбора платы (`BoardLink`: COM-порт или «По сети…» с паролем проекта); при
   заливке отладка отпускает связь и подключается снова — как сейчас с USB.
4. **`crablogic monitor`** — на `MasterSession` (+ `--host`); **ИИ** (`live_values`) — на `MasterSession`, адрес из
   `[board] host`, если он задан. Это заодно чинит `monitor` и живые значения ИИ с Rust-мастером.
5. **`crablogic upload-wasm --host`** — через `open_link`, как `gen-wasm --upload`.
6. **USB главнее сети.** Плата (`board/io.rs`, `netcmd.rs`): `crab-io` читает USB всегда; байты по USB при вошедшем
   клиенте — `netcmd::kick_for_usb()` (клиенту `err busy usb`, отключение, очистка разборщика), затем идут в
   разборщик; время последней команды по USB — атомарное, вход по сети в течение 10 с после неё — `err busy usb`.
   Мусор на линии (одиночные `
`, шум при подключении кабеля) не считается: только непустая строка или данные
   заливки. ПК: `crab-build::choose_link(board_config, password)` — порт есть в `serial_ports()` → USB, иначе
   `host` → сеть, иначе ошибка «плата не подключена»; редактор, `gen-wasm --upload`, `monitor`, ИИ — через неё
   (явные `-p`/`--host` в командной строке главнее).
7. **Справка:** `05-build.md`, страница онлайн-отладки, `09-news.md`; справка ИИ/`monitor`, если там описан порт.

## Риски

- Постоянный опрос по сети нагружает Wi-Fi и `crab-netcmd`: замерить опоздания шага под отладкой (критерий 4).
- Плата держит одного клиента: редактор не должен открывать вторую связь (заливка — только после остановки опроса).
- Тихий обрыв Wi-Fi: TCP может долго не замечать — сессия считает плату молчащей через 3 с и переподключается.
