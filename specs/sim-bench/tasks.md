# Задачи

- [x] `Bench`, `Signal`, `Ctx.bench`, `Behavior::drive` + тесты значения сигнала во времени.
- [x] `digital_in`, `analog_in`: тесты подтяжки и инверсии.
- [x] `dht22`, `ds18b20`: период, линейное изменение, ошибка (`ok=false`, значение держится).
- [x] `digital_out`, `pwm_out`: инверсия, разрешение записи, состояние пина.
- [x] `crab-sim`: стенд в `Simulation`, сохранение при пересборке; тест «кнопка → светодиод».
- [x] Меню порта в редакторе; справка (`help/`), архитектура, docs блоков.
- [x] Состояние выходного пина (`HIGH/LOW`, для ШИМ — `%`) внутри блока выхода в редакторе; тест `output_pin`.
- [ ] Ручная проверка меню и подписи в окне редактора (не проверено глазами).
- [ ] Изменение переменной по времени (запрошено 17.11.2026): у числовой переменной (`int`/`float`) в меню порта `var_get` в симуляции — «От … до … за, с», как у датчиков стенда: значение идёт линейно от «от» до «до» за заданное время и остаётся на «до»; по желанию «повторять» (пила или треугольник). В `Simulation` — список разгонов (переменная, от, до, длительность, момент старта), применяется в каждом такте до расчёта блоков, сбрасывается `reset`, переживает пересборку (как `keep_vars`). Проверка: тест в `crab-sim` (значение в момент t = от + (до − от) · t / T, после T держится), снимок меню. Булевы переменные и строки — вне задачи.
- [ ] То же для аналогового входа стенда (`analog_in`, запрошено 17.11.2026): сейчас у него одно число (отсчёты АЦП 0…4095), нужно «от … до … за, с» (и «повторять»), как у датчиков: значение пина идёт линейно по времени. Переиспользовать `Signal` стенда (канал аналогового пина) и меню `BenchInput::Sensor`; цифровые входы вне задачи (у них уровень). Проверка: тест в `crab-blocks`/`crab-sim` (АЦП в момент t), меню в редакторе.
- [ ] То же в отладке на плате (запрошено 17.11.2026): у форсировки числового выхода в меню порта — режим «менять от … до … за, с (повторять)». Мастер хранит только постоянное форсированное значение, поэтому разгон ведёт редактор: по таймеру шлёт новое форсированное значение с частотой опроса отладки (5–7 раз в секунду, не чаще — шаг заметен как ступеньки, это сказать в справке), «Снять форсировку» и закрытие отладки останавливают разгон и снимают форсировку. Проверка: тест генератора значений разгона (общий с симуляцией, лучше вынести в `crab-core`), ручная — на плате.
- [x] (заменено спекой `specs/debug-interaction`: ЛКМ/ПКМ по `bool`, окошко числа, 20.11.2026) Двойной щелчок по выходу вместо меню (запрошено 17.11.2026, уточнено в тот же день): двойной щелчок левой кнопкой по выходу блока — `bool` инвертируется сразу; число или строка — рядом с выходом появляется поле ввода (фокус сразу в поле, можно печатать без щелчка; Enter применяет и закрывает поле, Esc отменяет и закрывает; щелчок мимо тоже закрывает). В симуляции это задаёт ручной выход или переменную (`var_get`), в отладке — форсирует значение (для `bool` инверсия форсированного, для числа и строки поле ввода, форсировка остаётся до «Снять форсировку» в меню). Меню по правой кнопке остаётся (разгон, «Ошибка датчика», снятие форсировки). Подсказка в справке и в подсказке порта. Проверка: тест логики (инверсия, разбор введённого значения), ручная проверка мышью. Строки в отладке: форсировка строк пока не поддерживается мастером (`Live string ... not forceable`) — для них поле ввода только в симуляции, пока мастер не научится.
