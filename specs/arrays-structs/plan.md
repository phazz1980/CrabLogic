# План: массивы и структуры

Как делаем то, что описано в `spec.md`. Места в коде названы по поиску; точные сигнатуры уточняются при
реализации (отмечено «проверить»).

## Данные проекта (`crab-core`)

- Рядом с `Var` (`vars.rs`) появляются `ArrayVar` и `StructVar` в отдельных таблицах `Logic.arrays` и `Logic.structs` (`crab-core/src/arrays.rs`; отдельные, чтобы не менять `Var`, который собирают литералом в десятке мест); имена массивов, структур и переменных не должны совпадать (проверка — задача 2): у массива
  имя, тип элемента (`bool`, `int`, `float`, `byte`, `string`), длина, для `string` — предел длины строки, таблица
  начальных значений (`init`, короче длины — остальное нули или пустые строки); `retain` в первой версии нет; у структуры — имя и список полей `{имя, тип}`. Формат TOML: `[[array]]`, `[[struct]]` с `[[struct.field]]`; старые проекты читаются без изменений (скаляр по умолчанию).
- Предел длины: 256 на ESP32 и S3, 64 на C3 — проверка по плате проекта, сообщение в проверке схемы.
- `SignalType` и проверка типов портов не меняются: блоки берут массив параметром `array` (имя переменной),
  по проводам идут только индекс, значение и поля.
- Проверка схемы (`check/`): несуществующий массив или поле, индекс-константа вне длины, запись в один массив
  с нескольких листов (как у скалярной переменной: писать можно только из одного места), `retain`.

## Блоки (`library/`, `crab-blocks`)

Группа «Массивы». Массив из дерева тянется на лист блоком «Массив: элемент» с портами `index` и `value`: подключён выход `value` — блок читает, вход — пишет, вторая сторона недоступна (как у переменной). Остальные блоки: `array_fill`, `array_copy`, `array_sum`, `array_min`,
`array_max`, `array_find`, `array_shift` (кольцевой буфер: затирает самый старый), `array_stack` (push/pop,
выходы `empty`/`full`; полный стек не принимает элемент, флаг и счётчик отказа), `struct_pack`,
`struct_unpack`. Параметры блока описывают тип элемента и массив/структуру. Индекс вне границ: чтение даёт 0 и
`err = true`, запись пропускается и считается в счётчике отказов (по правилам надёжности платы).

## Сборка модулей (`crab-codegen`)

- Массив — область линейной памяти модуля листа (`wasm/`, отдельный файл `array.rs`); общий массив разных листов
  работает как строки и общие переменные (механизм общих переменных, проверить в `wasm/mod.rs` и
  `specs/module-ram`). Размер входит в оценку ОЗУ (`estimate.rs`, `crab.mem`): не помещается — ошибка сборки.
- Открытый вопрос из плана: хватит ли ядра WASM без новых функций мастера. Ожидаем, что да (обычные `load/store`);
  если нужны общие области между листами — добавить возможность мастера (`modcaps`), решить до задачи 5.
- Начальные значения: таблица записывается при старте модуля. `retain` в первой версии нет.

## Отладка и симуляция

- `crab-debug/image.rs`: элементы массива — слоты `ImageLayout` (по порядку, тип по элементу); форсировка элемента.
- `crab-sim`: массив в симуляции с теми же правилами границ; одинаковый результат с платой (критерий 3).
- Редактор: строка массива в дереве слева (папка «Переменные»), таблица значений в окне свойств и в окне
  «Значения»; диалог создания массива и структуры (`dialogs/forms.rs`).

## Риски

- ОЗУ на C3 (массивы в модулях рядом с Wi-Fi и MQTT) — отсюда предел 64 и оценка при сборке.
- Рост образа отладки: массив из 256 элементов даёт 256 слотов, возможно, нужны диапазонные кадры (решить в
  задаче отладки, замерить кадр и период опроса).
- Общие массивы между листами и порядок записи — вынесены в отдельную задачу с тестом.
