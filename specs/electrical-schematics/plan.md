# План: электрическая документация щита

## Затронутые крейты

- **`crab-core`** — модель щита: новый файл проекта `panel.toml` (в архиве рядом с `project.toml`;
  старые проекты без него читаются как раньше), проверка щита (`check/panel.rs`), правки для
  редактора и ИИ (`edit_panel.rs`). Ядро о рисовании ничего не знает.
- **`crab-schematic`** (новый) — раскладка и рисование листов. Вход: `Project` + `Library`; выход:
  разметка Typst. Символы IEC 60617 — свои, векторные, в коде. Язык подписей — параметр `Lang`
  (ru/en) со своей таблицей строк: `i18n` живёт в редакторе, ядру и крейту он недоступен.
- **`crab-pdf`** — общий хелпер Typst (`PRELUDE`, запуск `crablogic-pdf`) выносится так, чтобы
  `crab-schematic` пользовался им же. Отдельный PDF `panel.pdf` кладётся в архив при сохранении,
  если щит не пуст.
- **`crab-cli`** — команда `crablogic panel <проект> [--lang ru|en] [-o файл.pdf]`; `check` проверяет щит.
- **`crab-editor`** — режим «Щит»: над центром две вкладки «Логика» / «Щит». В режиме «Щит» слева дерево
  устройств по образцу дерева проекта (`panels::add_group`, `drag_row`, `row_label`; текст через
  `i18n::tr`), в центре предпросмотр листов (та же картинка, что в PDF; без интерактива; переключение
  страниц и языка, кнопка «Собрать PDF»), справа свойства выбранного устройства и список типов для
  добавления. Режим «Логика» не меняется. Место в центре готовится под ручную правку листа (позже).
- **`crab-mcp`/`crab-ai`** — общие команды: прочитать щит, добавить устройство, привязать, собрать документацию.

## Формат `panel.toml`

```toml
supply = "ac230"            # dc24 | ac230 | ac400

[[device]]
id = "K1"                   # обозначение по IEC 81346: -K1
kind = "contactor"          # ввод, автомат, УЗО, БП, контактор, реле, двигатель, нагрузка, клеммник, датчик, кнопка
rating = "230 В, 9 А"
part = ""                   # артикул, вводится вручную
bind = "pump"               # выход/вход проекта (блок.порт или имя тега)
load = "M1"                 # что коммутирует (для K*, Q*)
```

Блоки и теги не меняются. Связи «выход → катушка» берутся из `bind`.

## Как строится документ

1. **Модель цепей.** Из устройств и привязок строится граф цепей: питание → защита → коммутация →
   нагрузка, цепи 24 В, клеммы платы. Номера клемм и проводов выдаются детерминированно (по порядку
   обозначений); стабильность между пересборками — хранение выданных номеров в `panel.toml`, пока
   цепь не менялась.
2. **Раскладка.** Лист A4 книжный, колонки шириной ~20 мм; устройства ставятся по колонкам, порядок
   берётся из списка. Не поместилось — перенос на следующий лист со ссылкой «лист N, колонка M».
3. **Перекрёстные ссылки.** После раскладки каждому изделию присваивается «лист/колонка»;
   ссылки на катушки и контакты подставляются вторым проходом.
4. **Вывод.** Typst-разметка в той же системе координат, что у `crab-pdf` (единица — четверть мм).
   Страницы: титульный, силовая часть, цепи управления, клеммник, провода, спецификация.

## Риски

- **Раскладка** — самая трудоёмкая часть. Первая версия: жёсткая сетка колонок без оптимизации
  пересечений; сложные случаи выносятся в «ручную правку» (вне первой версии).
- **Число символов IEC** — первая версия ограничена перечнем из сценариев; остальное — позже.
- **Typst-хелпер** собирается отдельно; без него PDF не строится (как сейчас с `boards.pdf`) —
  ошибка по-русски, остальное не ломается.
- **Срочность.** Порядок задач такой, чтобы PDF со схемой появился на втором-третьем шаге, а
  редактор и ИИ не блокировали выпуск.
