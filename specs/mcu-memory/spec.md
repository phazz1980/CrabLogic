# Экономия памяти мастера на ESP32-C3

Продолжение `specs/wasm-on-mcu/` (мастер-прошивка с WASM-модулями) и `specs/pubsub-bus/`.

## Цель
На ESP32-C3 мастеру с одним модулем Wi-Fi + MQTT не хватает кучи: свободно ~5,7 КБ, Wi-Fi берёт ~54 КБ,
второй модуль или замена модуля на лету уже не проходят. Нужно, чтобы мастер на C3 работал с Wi-Fi, MQTT
и несколькими модулями с запасом. Главные причины, найденные при разборе кода:

| Где | Сколько сейчас | Почему много |
|---|---|---|
| Память модуля со строками | 64 КБ на модуль | WASM выделяет память страницами по 64 КБ, модулю нужно несколько КБ |
| Стек основного цикла | 16 КБ | нужен только тестовым командам `tick`/`put` |
| Массивы слотов (события, очередь, выходы, форсировка) | ~15 КБ на 4 слота | выделены всегда, даже для пустых слотов |
| Стек задачи модуля | 8–16 КБ на модуль | запас под глубокую рекурсию при компиляции модуля |
| Копия модуля в ОЗУ | размер `.wasm` (5–20 КБ) | wasm3 ссылается на байты модуля всё время работы |
| Буфер приёма по USB | 4 КБ | модуль приходит одним куском |
| Буферы MQTT, журнал | ~4 КБ | рассчитаны на сообщения длиннее, чем бывают в модулях |

## Сценарии
1. Пользователь собирает проект «датчик → MQTT» для C3, заливает мастер и модуль. Плата подключается к Wi-Fi и
   брокеру, работает сутками, в `info` видно, сколько памяти свободно и сколько занял каждый модуль.
2. На той же плате пользователь добавляет второй модуль (логика, веб-страница) — он запускается без «нет памяти».
3. Пользователь меняет модуль на лету — замена проходит, память после неё не уменьшается от раза к разу.
4. Модулю не хватило выделенной ему памяти (ошибка расчёта): он останавливается с понятной записью в журнале,
   остальные модули и плата продолжают работать.
5. Модуль, собранный старой версией, не запускается: в журнале и в редакторе — просьба пересобрать его.

## Критерии готовности
- `info` показывает: свободную кучу, наибольший свободный блок, минимум кучи с момента старта; по каждой задаче —
  сколько стека осталось; по каждому модулю — размер его памяти и скомпилированного кода.
- Модуль со строками получает столько памяти, сколько ему нужно (с запасом), а не 64 КБ. Размер считается при
  сборке; выход модуля за свою память — остановка модуля с записью в журнале, а не порча чужой памяти
  (проверяется тестовым модулем).
- Пустой слот не занимает памяти под события, очередь и выходы.
- Стек основного цикла и задач модулей задан по замерам, а не «с запасом»; замеры записаны в `plan.md`.
- На C3 с Wi-Fi + MQTT и одним модулем свободно не меньше **40** КБ, наибольший блок не меньше 16 КБ;
  два модуля (MQTT + логика) запускаются; 20 замен модуля подряд не уменьшают свободную кучу.
- Обычный ESP32 (DevKit) работает как раньше; все тесты `crab-build`/`crab-codegen` проходят.
- Справка (раздел про мастер и ограничения плат) обновлена.

## Вне задачи
- Пересборка ESP-IDF под свои настройки Wi-Fi/lwIP (буферы Wi-Fi остаются как в ядре Arduino).
- Прямая прошивка C++ без мастера (там этой проблемы нет).
- AVR и STM32.

## Решения (ответы пользователя, 08.11.2026)
1. Норма: на C3 с Wi-Fi + MQTT и одним модулем свободно **не меньше 40 КБ**.
2. Модули хранятся во флеше без копии в ОЗУ — **в этой задаче** (своя таблица разделов).
3. Заливка модуля частями с подтверждением, буфер USB уменьшается — **в этой задаче** (меняется протокол `put`).
4. Работа `tick`/`put` с wasm3 переносится из основного цикла в задачу модуля, стек цикла уменьшается.
5. Старые модули без сведений о памяти **не запускаются**: в журнале — просьба пересобрать модуль.
