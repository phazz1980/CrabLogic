# План: экономия памяти мастера на ESP32-C3

Спека: `spec.md`. Затронуты: мастер `specs/wasm-on-mcu/proto/master/master.ino`, `crab-codegen` (модуль
сообщает размер памяти), `crab-build` (`master.rs` — разделы, `mcu_module.rs` — протокол заливки),
справка про мастер, раздел архитектуры про хранение модулей.

## 0. Замеры (первым, по ним настраиваются п. 3–4)
Ответ `list` дополняется (сделано так, а не в `info`: редактор уже опрашивает `list` раз в секунду):
- строка `free=<free> largest=<largest> min=<min>`: `ESP.getFreeHeap()`,
  `heap_caps_get_largest_free_block(MALLOC_CAP_8BIT)`, `esp_get_minimum_free_heap_size()`;
- строка `stack=<задача>:<не тронуто байт>,...` по `uxTaskGetStackHighWaterMark` для loop, hardware, wdt и задач модулей;
- у модуля `mem=<байт памяти wasm> code=<байт страниц кода wasm3> wasm=<байт модуля>` (перед `crc=`).
Редактор показывает это в окне состояния платы. Замеры C3 «до» и «после» каждого пункта пишутся сюда, в конец.

## 1. Память модуля по потребности
- `crab-codegen`: модуль получает пользовательскую секцию `crab.mem` (u32 — байт памяти, нужных модулю:
  `mem_top`, выровненный до 16, плюс 64 байта запаса). Модуль без строк — `0`. Секция видна и инструментам.
- `crab-build`: размер берётся из секции и уходит в заголовок заливки (`mem=N`, см. п. 5).
- Мастер: перед `m3_LoadModule` — `s.rt->memoryLimit = N` (N мастер читает из секции `crab.mem` самого модуля, так
  работают и модули, загруженные при старте из хранилища; `mem=` в заголовке `put` — для сведения) (поле уже есть в нашей копии wasm3, `m3_env.c:370`).
  Нет `mem=` — модуль не запускается: «модуль собран старой версией, пересоберите его».
- Выход за память: wasm3 сравнивает адрес с реальной длиной памяти и возвращает ловушку; `inMem` тоже берёт
  реальную длину. Тест: модуль, пишущий за `mem_top`, останавливается с записью в журнале.

## 2. Работа `tick`/`put` с wasm3 — не в основном цикле
- `tick`: цикл ставит модулю запрос «сделай n шагов по dt» и ждёт уведомления задачи модуля
  (`xTaskNotify`); шаги выполняет задача модуля на своём стеке.
- Загрузка и компиляция модуля (`startSlot`) — во временной задаче со своим стеком (по замеру 8 КБ), которая
  удаляется после `m3_CompileModule`. Задача модуля потом только выполняет код.
  Временную задачу удаляет вызывающий (`vTaskDelete(t)`), а не она сама: стек задачи, удалившей себя,
  освобождает задача простоя, а зависший модуль её не пускает — каждый перезапуск сторожем терял 16 КБ
  (найдено на плате: после трёх перезапусков `hang` свободно 7,6 КБ).
- `SET_LOOP_TASK_STACK_SIZE` — по замеру: 6 КБ.

## 3. Стек задачи модуля по замеру
После п. 2 рекурсии компилятора в задаче модуля нет. Стек = база по замеру на примерах (насос, MQTT,
300 блоков) с запасом 1,5 КБ; `taskStackFor` пересчитывается по замерам. Если `m3_CompileModule` не
компилирует всё заранее (ленивая компиляция в нашей версии wasm3) — проверить и при необходимости вызвать
компиляцию всех функций явно.

Сделано: `m3_CompileModule` компилирует каждую функцию с телом, мастер вызывает её во временной задаче.
Замер: задача модуля тратит до 2,1 КБ (300 блоков с MQTT, `math_more`), загрузка — до 1,8 КБ.
Стек модуля — постоянные 5 КБ (`taskStackFor` убран): 2,1 КБ + 1,5 КБ запаса + место под тяжёлые функции
мастера (форматирование текста, Sparkplug), которые на C3 не замерены.

## 4. Слоты без постоянных массивов
`Slot` делится на постоянную часть (имя, состояние, счётчики) и `SlotData`, выделяемую при старте модуля:
выходы, форсировка — по числу наблюдаемых выходов модуля (`out=N` в заголовке, ≤ 128); очередь шины — по
`qCap`; события — 32 вместо 128 (окно графика редактор забирает каждые 100–200 мс, проверить по `evLost`).
Остановка модуля освобождает `SlotData`. Ожидаемо: ~15 КБ → ~0 для пустых слотов, ~1–2 КБ на модуль.

## 5. Модули в разделе флеша без копии в ОЗУ; заливка частями
- Своя таблица разделов мастера (`partitions.csv` рядом со скетчем, вместо схемы `no_ota`):
  `nvs`, `app` (как сейчас ~2 МБ), `crabmod` — 16 областей по 68 КБ (заголовок 256 байт + модуль до 64 КБ;
  новая версия пишется в свободную область, старая работает до переключения — горячая замена и откат при
  сбое заливки), `coredump`. Схема `no_ota` в опциях платы остаётся — по ней arduino-cli проверяет размер
  приложения (те же 2 МБ).
  LittleFS из мастера убирается целиком (он хранит только модули) — экономит и его кэш в ОЗУ.
- Область: заголовок (магия, версия, имя, длина, CRC32, `mem`, `out`, права, номер поколения) + байты модуля.
  Модуль отображается в адреса через `esp_partition_mmap` (данные) — `s.wasm` указывает во флеш.
  При старте мастер выбирает для каждого имени область с годным CRC и бо́льшим поколением.
- Протокол: `put <name> <len> <crc> <права|-> mem=<N>` → мастер стирает свободную область →
  `ready <chunk>` (chunk = 512, `mem` модуля мастер берёт из секции `crab.mem`) → по кускам: хост шлёт ≤ chunk байт, мастер пишет `esp_partition_write`
  и отвечает `ack <смещение>` → в конце проверка CRC по флешу, запись заголовка, замена → `swap_us=…`, `ok`.
  Буфер приёма Serial — 1 КБ вместо 4 КБ. Буфера на весь модуль в ОЗУ больше нет (сейчас `cmdPut` берёт
  `malloc(len)` — до 64 КБ, на C3 это само по себе не проходит).
- `del` стирает заголовки областей имени. `modcaps` получает `flashmod`; редактор с мастером без него
  просит перешить мастер (после перешивки модули заливаются заново — таблица разделов другая).
- `crab-build/master.rs`: кладёт `partitions.csv` в папку сборки мастера; тест вместо
  `master_takes_the_no_ota_partitions`. Плата с явно заданной в проекте схемой разделов — ошибка
  «у мастера своя таблица разделов».

## 6. Мелочи
`FLPROG_MQTT_MAX_PACKET_SIZE` = 384 (строки модулей ≤ 128 байт; задаётся `-D` при сборке мастера, библиотеку
не правим), журнал 16 × 64 байта, очередь публикаций MQTT — по `max subscriptions`/настройке модуля.

## Риски
- wasm3 читает байты модуля побайтно и не пишет в них — проверить по исходнику (`m3_parse.c`, `m3_compile.c`);
  если пишет хоть где-то — оставить копию в ОЗУ только для этой части.
  **Проверено:** `bytes_t` = `const u8 *`, записи нет; но wasm3 хранит указатели в байты модуля (имена,
  тела функций для компиляции), поэтому отображение флеша живёт столько же, сколько модуль (`munmap` — в
  `stopSlot`).
- **Найдено на C3:** скомпилированный код wasm3 лежит в куче и занимает ~3,2 × размер `.wasm`
  (`code=` в `list`). С Wi-Fi + MQTT модуль 14,6 КБ (600 блоков) работает, свободно 36 КБ; 24 КБ (1000 блоков)
  не компилируется даже без старой версии («memory allocation failed»), 40 КБ — тем более. Хранение и заливка
  до 64 КБ работают, предел — память под код. Мысль на потом: делить большой лист на несколько модулей.
- Чтение из отображённого флеша медленнее ОЗУ и стоит места в кэше; запись во флеш (заливка другого модуля)
  на время останавливает кэш — проверить, что такт модулей и Wi-Fi это переживают (замер `periodMax`).
- Размер приложения мастера с Wi-Fi + веб + MQTT должен влезать в раздел `app` новой таблицы.
- Планы SD-карты (архитектура, `specs/sd-card/`): с карты модуль отобразить нельзя — там понадобится копия в ОЗУ;
  слой хранения делаем с этой развилкой.
- Перешивка мастера стирает старые модули — сказать в справке и в сообщении редактора.
