# План: карта SD — архив и журнал

## Как устроено сейчас

- Шины SPI мастера (`board/bus.rs`): у драйверов `block.wasm` свой хост — SPI3 на ESP32 (SPI2 держит W5500), SPI2
  на C3 (он же у W5500: вместе с Ethernet драйверы SPI на C3 не открываются). Передачи драйверов идут из потока
  схемы, замок `Spin` без соперника.
- Образец «запись из шага в фон»: `board/retain.rs` — ограниченная таблица, поток `crab-nvs`, уведомление задачи,
  переполнение считается, отчёт в журнал. Образец «настройки едут с модулем»: блоки `wifi`, `ethernet`, `mqtt`.
- Команды мастера идут через общий разборщик (`board/io.rs`) — значит, и по USB, и по сети (вход 4040).
- Время: блок `ntp` ставит системные часы; без него — только время от включения.

## Решение

1. **Мастер, `board/sd.rs`** (новый) и возможность `sd` в `modcaps`:
   - Настройку присылает модуль один раз (выводы SCK/MOSI/MISO/CS, частота): карта садится на хост драйверов SPI
     как ещё одно устройство (свой CS). Если шина ещё не открыта — SD открывает её на своих выводах; открыта на других
     выводах — ошибка «карта SD: шина SPI уже на выводах …». На C3 с W5500 — ошибка, как у драйверов SPI.
   - Монтирование FAT (`esp_vfs_fat_sdspi_mount`, `/sd`, без форматирования) и вся работа с файлами — в фоновом потоке
     `crab-sd` (стек ~6 КБ, ядро 0 на ESP32). Нет карты / ошибка — повтор раз в 5 с (вставили — заработало).
   - Из шага: `sd_append(файл, строка)` кладёт строку в кольцевой буфер (4 КБ, «попытка» `Spin`), не ждёт; не влезло —
     счётчик потерянных строк. Поток дописывает строки в `/sd/<имя>/<ГГГГ-ММ-ДД>.csv` (без часов —
     `/sd/<имя>/boot<N>.csv`, N растёт в NVS), сбрасывает на карту (`fsync`) раз в 2 с — при пропаже питания теряется
     не больше 2 с.
   - Кольцо: перед новым файлом и раз в минуту, если свободно < 5 % или < 4 МБ, удаляются самые старые файлы (по
     имени) во всех папках архива.
   - Состояние для модуля: готова, свободно (МБ), потеряно строк, ошибок; строка `sd …` в `info`; события в журнал.
   - Команды (USB и сеть): `sd ls` — файлы, размеры; `sd get <путь> <смещение> <длина>` — кусок файла (заголовок
     `data <n>` + n байт, как у `put` в обратную сторону, до 2 КБ за раз); `sd rm <путь>`. Чтение — в потоке `crab-io`
     через FAT (своя блокировка FATFS), без участия шага.
2. **Блоки** (встроенные, `crab-blocks` + `library/<блок>/block.toml`, `docs.md`):
   - `sd_card` — настройка (выводы, частота), выходы `ready`, `free_mb`, `lost`, `errors`; один на плату.
   - `sd_archive` — до 8 входов (bool/int/float), период (мс), имя папки, имена столбцов (по умолчанию — подписи
     связей); строка `ГГГГ-ММ-ДД чч:мм:сс;зн1;зн2…` (разделитель `;`, десятичная запятая — для Excel в русской
     локали), заголовок столбцов — первой строкой нового файла.
   - `sd_log` — вход-фронт `trig`, текст (строка или константа), имя папки; строка `время;текст`.
3. **`crab-codegen`**: вызовы `sd_*` мастера, право `sd` в `allow`, проверка «один `sd_card` на проект».
4. **ПК:** `crab-build/sd_files.rs` — `list`, `get` (кусками, проверка длины), над `Link` (USB или сеть, выбор связи
   как у отладки). `crablogic sd проект ls | get <файл> [куда] | pull [папка]` (`pull` — всё новое). Редактор:
   «Плата → Файлы на карте SD…» — список, «Скачать», «Скачать всё».
5. **Справка:** новая страница или раздел «Архив на карте SD» (подключение, формат, кольцо, пропажа питания, как
   забрать), `docs.md` трёх блоков, новости; пример `examples/sd_archive`.

## Риски

- **Общая шина SPI на C3** (и на ESP32 при драйверах SPI): передача карты (запись блока 512 Б, до единиц мс) и
  передача драйвера из шага делят хост — шаг может ждать шину. Мера: карта пишет из буфера крупными кусками редко
  (раз в 2 с), замер `late50/late100` с драйвером SPI и картой вместе; если плохо — на ESP32 карта на SPI2 без
  Ethernet, на C3 — в справке «карта и драйверы SPI вместе дают задержку до N мс».
- **Флеш мастера** (~80 % раздела): FAT + SDSPI +30–40 КБ — проверить размер на обеих платах.
- **Куча C3 с Wi-Fi:** буферы FAT ~4–8 КБ + стек потока; поток и буферы — только когда есть `sd_card` в модуле.
- **Пропажа питания:** FAT может потерять последний кусок или длину файла — `fsync` раз в 2 с, проверка выдёргиванием.
- Нет карты для теста? — нужна карта microSD и модуль-переходник SPI (спросить пользователя).
