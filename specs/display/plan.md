# Дисплеи и меню — план

## Данные проекта

Экраны и меню живут в `web.toml` вместе с веб-страницей (общий конструктор): это та же `Logic` из блоков, что
и сейчас (`crab-core/src/project.rs`, `WEB_FILE`).
- Новые виды виджетов-блоков: `disp_text` (статичный текст), `disp_value` (число: формат, единицы),
  `disp_bar` (полоса: min, max), `disp_led` (индикатор), `disp_icon` (значок из набора). Параметры: `display`
  (id блока дисплея), `screen`, `x`, `y`, `w`, `h` (пиксели OLED или знакоместа LCD), `font` (8/16, только OLED).
  Описания — `library/disp_*/block.toml` с классом «виджет экрана» (как `web_*`: в палитру не попадают).
- Меню — блоки `menu_item` в `web.toml`: `menu` (id блока меню), `parent`, `order`, `kind`
  (submenu | number | bool | choice | action | view), `caption`, `var` (переменная схемы), `min`, `max`, `step`,
  `unit`, `choices`. Параметр меню пишет в переменную; сохранение — флаг `retain` у этой переменной
  (`crab-core/src/vars.rs`), его ставит конструктор.
- Защита флеша (`specs/retain-wear`): пока оператор листает значение кнопками, оно живёт только в памяти
  меню; в переменную оно попадает по «ОК» и сразу сохраняется во флеш (минуя покой и период `retain`),
  «Назад» отменяет правку. Одна правка уставки — одна запись.
- Теги: виджет экрана с вводом не бывает, поэтому каждый `disp_*` (кроме `disp_text`/`disp_icon`) даёт один тег
  `<id>.in` — значение из схемы на экран. Механизм тегов, переименования и удаления — общий с веб-виджетами.

## Блоки на листе

- `oled` (вид: ssd1306_128x64 | ssd1306_128x32 | sh1106_128x64; адрес; `sda`/`scl` с `bus`; вход `screen`;
  выход `ok`) и `lcd` (1602 | 2004; адрес PCF8574; те же шины; вход `screen`, `backlight`; выход `ok`).
- `menu`: параметры `display` (id блока дисплея), `timeout` (30 с); входы `up`, `down`, `ok`, `back`;
  выходы `open`, `item`, `changed`.

## Исполнение на плате

Один драйвер-модуль `drivers/display` (Rust `no_std` → `library/oled/block.wasm`, `library/lcd/block.wasm`;
общий крейт отрисовки и меню, два входа сборки). Внутри: шрифты 8×8 и 8×16 (латиница, кириллица, цифры,
знаки), кадр OLED 1 КБ, отрисовка виджетов, движок меню; LCD — строки + до 8 своих символов CGRAM на экран.
Кадр уходит частями: одна страница OLED (128 байт) или одна строка LCD за шаг, только изменённые (≤ 5 мс).

Связь с листом (`crab-codegen/src/wasm/user_block.rs`):
- **новый импорт `crab.config(ptr, cap) -> len`**: генератор кладёт в данные модуля листа описание экранов и
  меню этого дисплея (компактный двоичный формат, версия в первом байте) и отдаёт его драйверу при `init`;
- входы драйвера после его собственных портов — значения виджетов его экранов по порядку таблицы, затем входы
  блока меню, привязанного к этому дисплею, и текущие значения переменных меню; выходы после собственных — выходы
  меню и новые значения переменных (генератор пишет их в переменные, когда меню сообщает об изменении).
  Блок `menu` своего кода не имеет: генератор присоединяет его порты к экземпляру выбранного дисплея.
- Мастер-прошивку не трогаем: всё внутри модуля листа (шины I²C уже есть).

### Договорённость генератора и драйвера (13.11.2026)

Конфиг — `crab-ui-format` (`Config`), его отдаёт `crab.config`. Индексы `crab.input(i)` / `crab.output(i, v)`:

| Входы | Индексы |
|---|---|
| свои порты блока по `block.toml` (`oled`: `screen`; `lcd`: `screen`, `backlight`) | `0 .. P` |
| значения виджетов: `Widget.input = k` → | `P + k`, `k < W` (W = число виджетов с входом) |
| если есть меню: `up`, `down`, `ok`, `back` | `P + W .. P + W + 4` |
| текущие значения переменных меню: `MenuItem.var_slot = v` → | `P + W + 4 + v`, `v < V` |

| Выходы | Индексы |
|---|---|
| свои порты (`ok`) | `0 .. Q` |
| если есть меню: `open` (0/1), `item` (номер пункта), `changed` (импульс 0/1) | `Q .. Q + 3` |
| `changed_slot`: номер `v` переменной, подтверждённой «ОК» в этом шаге, иначе −1 | `Q + 3` |
| новое значение переменной `v` | `Q + 4 + v` |

Генератор: в шаге, где `changed_slot = v ≥ 0`, пишет выход `Q + 4 + v` в переменную пункта и сохраняет её во флеш
сразу (минуя покой и период `retain`). Порты блока `menu` генератор соединяет с входами/выходами меню дисплея,
выбранного в его параметре `display`. Значения bool и choice передаются как 0/1 и номер варианта (f64).
Виджет значения: `format = 0` — число с `decimals` и затем `unit`; `format = 1` — `unit` содержит шаблон с `%v`
(«Т = %v °C»). Пункт-действие: генератор сам даёт переменной импульс на один шаг, когда `changed_slot` = её номер.
Параметры дисплея в драйвере: `model` (строка, ячейка 0 — вид берётся из `Config.display`), `address` = 1, `sda` = 2,
`scl` = 3. Блок `menu` должен стоять на листе дисплея; значения виджетов берутся с листа дисплея.

## Конструктор (`crab-web`, `designer.html`)

Список «Страницы» дополняется дисплеями проекта: выбор дисплея показывает его экран в натуральной сетке
(пиксели ×4 или знакоместа), набор виджетов `disp_*`, переключатель экранов. Вкладка «Меню» — дерево пунктов
выбранного блока меню (добавить, вложить, переставить, свойства, выбор переменной или создание новой с `retain`).
Предпросмотр рисует тем же шрифтом, что и плата (шрифт выгружается из крейта в JSON при сборке).

## Симуляция и редактор

`crab-sim`: драйвер дисплея выполняется и на ПК — заглушка шины разбирает команды SSD1306/SH1106/HD44780 и
держит картинку экрана; редактор показывает её в окне «Дисплей» при симуляции. Входы меню — как у любого блока.

## Проверка схемы

Виджет за пределами экрана; два дисплея на одном адресе одной шины; блок `menu` без дисплея или с несуществующим;
больше 8 разных русских букв на экране LCD (предупреждение); переменная пункта меню не того типа.

## Риски

- Размер драйвера: шрифт 8×16 с кириллицей ≈ 5 КБ, всё вместе должно уложиться в окно драйвера 32 КБ.
- Скорость I²C на ESP32-C3 и общая шина с другими драйверами: кадр частями, приоритет — не задерживать лист.
- Формат `crab.config` — новая точка ABI драйверов: описать в `help/12-drivers.md` и `Архитектура и план.md`.
