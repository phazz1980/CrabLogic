# Без f64 на плате

Продолжение `specs/numeric-model/` (там уже записано «`f64` не используется»), `specs/wasm-drivers/` и
`specs/display/`. Решение пользователя 13.11.2026: «не используй f64 в коде esp32».

## Цель
В коде, который выполняется на ESP32 и ESP32-C3, нет операций и ячеек `f64`: значения хранятся и передаются
как `i32` (`bool`, `int`) и `f32` (`float`). У ESP32 есть FPU только для `f32`, у C3 нет FPU вовсе, поэтому
каждая операция `f64` выполняется программно и отнимает время шага и ОЗУ.

## Решения пользователя
- (13.11.2026) `f64` в коде платы не используется.
- (13.11.2026) `f32` тоже не по умолчанию — только по необходимости. По умолчанию целые (`i32`, меньшие
  типы, фиксированная точка): `bool` и `int` идут как `i32`; `f32` — только там, где значение по смыслу
  дробное и задано типом порта `float` (вход/выход блока, переменная `float`). Внутри драйверов и мастера
  расчёты и форматирование — в целых (сырые единицы датчика, десятые/сотые, номера пунктов, шаги меню);
  в `f32` переводится только итог для порта `float`.

- (13.11.2026, ответы на вопросы) 1а — старые `block.wasm` с `f64` отклоняются с сообщением «пересоберите
  блок»; 2 — как дешевле по ресурсам: остаток `float` — нативный `fmodf` мастера (функция `crab.math`),
  округление — несколько инструкций `f32` прямо в модуле; 3 — строковые входы драйверов делаем здесь же;
  4А — новый виджет «Строка на экране».

## Где f64 сейчас (13.11.2026)
1. **Интерфейс блоков с `block.wasm`** (драйверы и свои блоки): `crab.input(i) -> f64`, `crab.param(i) -> f64`,
   `crab.output(i, f64)`, ячейки по 8 байт, на входе и выходе преобразования `i32/f32 ↔ f64`
   (`crab-codegen/src/wasm/user_block.rs`, `driver.rs`, `display.rs`).
2. **Драйверы** `drivers/display`, `dht22`, `ds18b20`: значения и расчёты внутри (меню: число, шаг, пределы,
   формат вывода).
3. **Модуль листа**: остаток от деления `float` (`%`) и округление `float → int` идут через `f64`
   (`crab-codegen/src/wasm/block.rs`).
4. **Мастер**: статистика замеров импульсов (`firmware/master-rs/src/board/pulse.rs`, 3 строки).
5. **Образцы и инструкции** для своих блоков: `skills/crablogic-block/examples/*`, справка о блоках на WASM.

Вне задачи: код на ПК (генератор, симулятор, редактор, константы при генерации) — там `f64` остаётся;
формат проекта не меняется.

## Сценарии
- Пользователь собирает проект с дисплеем, датчиками и своими блоками: в модуле листа и драйверах нет `f64`,
  результаты те же, что раньше (кроме округления до `f32`, которое и так было на входе в схему).
- Автор своего блока пишет его по образцу из `skills/` с входами `i32`/`f32` и строками; `crablogic block check`
  объясняет ошибку, если блок использует `f64`.
- Вход виджета дисплея принимает строку (`crab.input_text`), см. решение по виду виджета.

## Критерии готовности
0. Интерфейс блоков типизирован: целые входы/выходы/параметры передаются как `i32`, `f32` — только у портов
   `float`; ячейка целого — 4 байта.
0а. В драйверах `f32` встречается только при чтении/записи портов `float`; расчёты (меню, формат числа,
   датчики) — в целых. Проверка: обзор diff и тесты драйверов.
1. Проверка модуля листа: в собранном модуле (вместе с вклеенными драйверами) нет ни одной инструкции и
   типа `f64` — тест генератора на примерах `examples/*` и всех `library/*/block.wasm`.
2. `crablogic block check` отклоняет `block.wasm` с `f64` (или старым интерфейсом — по ответу на вопрос 1) с
   понятным сообщением и кодом ошибки.
3. Остаток `float` и округление совпадают с симуляцией на краевых значениях (тест эмиттера).
4. Драйверы дисплея, DHT22, DS18B20 пересобраны; их тесты проходят; снимки меню не изменились.
5. Бенч `crablogic bench` на ESP32 и C3 не хуже отчётов `bench/*-2026-11-13-*` (медиана нескольких заливок).
6. Справка, `docs.md`, образцы в `skills/` обновлены.

7. Виджет «Строка на экране» (`disp_string`) показывает строку схемы на OLED и LCD (обрезка по ширине),
   есть в конструкторе экранов, симуляции и примере `examples/display_menu`.

## Вопросы пользователю (отвечены, см. «Решения»)
1. **Старые `block.wasm` с `f64`** (ваши блоки в `user_library`, чужие блоки): (а) отклонять с сообщением
   «пересоберите блок по новому образцу» — советую; (б) пока поддерживать с предупреждением (тогда `f64`
   останется в модуле для таких блоков).
2. **Остаток `float` и округление без `f64`**: (а) точный алгоритм на `f32` в модуле (остаток — циклом
   вычитаний со сдвигом, медленнее на больших отношениях) — советую; (б) функция мастера на Rust (`fmodf`).
3. **Строки на дисплее** делаем в этой же задаче (новый интерфейс драйверов сразу с `input_text`)? Советую да.
4. **Виджет для строки**: (А) новый «Строка на экране» — советую; (Б) вход «Значения на экране» принимает и строку.
