# План: без f64 на плате

## Интерфейс блоков с `block.wasm` (драйверы и свои блоки), версия 2
Имена — как у импортов модуля листа (`crab-kernel/src/abi.rs`), чтобы автор видел одно и то же:

| Импорт | Подпись | Для |
|---|---|---|
| `crab.input_i(i)` | `(i32) -> i32` | вход `bool`/`int` |
| `crab.input_f(i)` | `(i32) -> f32` | вход `float` |
| `crab.input_text(i, ptr, cap)` / `crab.param_text` | `(i32, i32, i32) -> i32` | вход/параметр `string`: копия байтов в окно блока, результат — длина (обрезка по `cap`); имена и подписи — как уже в симуляции |
| `crab.output_text(i, ptr, len)` | `(i32, i32, i32)` | выход `string` (по возможности в этой задаче; иначе — отдельная) |
| `crab.param_i(i)` / `crab.param_f(i)` | `(i32) -> i32` / `(i32) -> f32` | параметры |
| `crab.output_i(i, v)` / `crab.output_f(i, v)` | `(i32, i32)` / `(i32, f32)` | выходы |
| `crab.log`, `crab.config`, `bus.*` | без изменений | |

- Ячейки значений по типу порта: 4 байта (`i32` или `f32`). Строковый вход — указатель и длина строки листа,
  прокладка копирует байты (`memory.copy`) в окно блока.
- Тип импорта должен совпадать с типом порта в `block.toml` (`input_i` у `float`-входа — ошибка проверки).
- Старые `crab.input/param/output` (`f64`) и модуль `flp` — ошибка «старый интерфейс с f64: пересоберите блок
  по образцу из skills/» (свой код ошибки в `help/08-errors.md`). Любая инструкция или тип `f64` в
  `block.wasm` — та же ошибка.
- Затронуто: `crab-codegen/src/wasm/{user_block,driver,display}.rs`, `block_check.rs`; `crab-sim/src/lib.rs`
  (хост на ПК, считает в `f32`/`i32` бит в бит); `crab-build/src/wasm.rs` и `crab-editor/src/blockedit/`
  (шаблоны своего блока на C/Rust); `skills/crablogic-block/` (образцы, инструкция).

## Модуль листа
- Округление `float → int`: `t = trunc(x); r = t + (|x − t| ≥ 0.5 ? sign(x) : 0)`, всё в `f32`
  (`x − t` точно), затем `i32.trunc_sat_f32_s`.
- Остаток `float`: вызов `crab.math(4, a, b)`; мастер — `libm::fmodf`, симуляция — `a % b` (`f32`).
  Сейчас в `math` ветка `_` — `powf`, поэтому `ABI_VERSION` 4 → 5: старый мастер откажется от модуля
  с понятным сообщением (мастер перезаливается).
- Проверка: тест генератора — в модуле нет `f64` (обход инструкций и типов, `wasmparser`).

## Драйверы
- `display`: значения меню и виджетов — целые с масштабом `10^decimals` (`i32`), шаг/пределы/формат в целых;
  `f32` только при чтении входа `float` и записи переменной `float`. `crab-ui-format` v3: числа пункта меню
  (`min`, `max`, `step`) — `i32` в единицах `10^-decimals`; полоса (`disp_bar`) хранит `min`/`max` как `f32`
  (вход `float`); новый вид виджета `String` со строковым слотом. v1/v2 читаются.
- Реализация v2 в генераторе (задача 2): ячейка значения — 4 байта по адресу `cells + 4*i`, тип ячейки — тип порта
  (`bool`/`int`/`duration`/`pin` — `i32`, `float` — `f32`); индекс вне диапазона читается как 0 и не пишется. Строковый
  порт держит неиспользуемую ячейку (индексы = индексы портов в `block.toml`), его текст идёт только через
  `input_text`/`param_text`/`output_text` (копия до `cap`, результат — число скопированных байт; для выхода — до ёмкости
  буфера сигнала, неверный диапазон игнорируется). Тип импорта должен совпадать с типом порта: `input_i` без
  `bool`/`int`-входов, `input_f` без `float`-входа и т. п. — ошибка генерации (видна в `block check`); v1 и v2 в одном
  блоке — ошибка. Слоты дополнений дисплея (входы после собственных портов блока, ячейки по 4 байта, тип по типу
  сигнала-источника): числовые виджеты (по одному на виджет плана; тип — тип порта `in` виджета), строковые виджеты
  (`STRING_WIDGETS` слотов в `user_block.rs`, сейчас 0; драйвер читает их `input_text(слот, …)`, числовая ячейка не
  используется), 4 кнопки меню `up/down/ok/back` (`i32`), переменные меню (по типу переменной). Выходы после собственных:
  `open`, `item`, `changed` (`i32`), индекс подтверждённой переменной (`i32`), затем по ячейке на переменную (по типу
  переменной). `input_text` на индексе строкового слота дополнения: индекс = число собственных входов + номер слота
  (строковые виджеты — сразу после числовых).
- Порядок слотов драйвера дисплея: свои порты, числовые виджеты, строковые виджеты, кнопки меню, переменные меню.
- `ds18b20`: сырые 1/16 °C в `i32`, `f32` только на выходе; `dht22`: десятые доли в `i32`, `f32` на выходе.
- Пересборка `library/{oled,lcd,ds18b20,dht22}/block.wasm`; снимки меню (`display_menu_picture`) не меняются.

## Решения при реализации задач 5 и 6 (13.11.2026)
- `crab-ui-format` версия 3: пункт «число» хранит `min`/`max`/`step` как `i32` в единицах `10^-decimals`; у каждого
  пункта байт `vflags` (бит 0 — переменная `float`: драйвер читает/пишет ячейку как `f32`, иначе `i32`); полоса
  хранит `min`/`max` как `f32`; вид виджета 5 `String` без нагрузки (слот в `input`). Версии 1 и 2 читаются:
  пределы переводятся в целые арифметикой `f32` (без `f64`), число с `decimals > 0` считается переменной `float`
  (в старых блобах флагов нет), у версии 1 меню без `font`/`hints` (16, подсказки включены).
- Драйвер дисплея: значение виджета «значение/полоса» всегда `float`-ячейка, светодиод — `bool`. Число из
  `f32` в единицы `10^-decimals` переводится целочисленно и точно (мантисса, показатель, округление от нуля),
  поэтому картинка не меняется. Редактируемое значение меню — `i32`; для переменной `float` обратно — одно деление
  `f32`. `f32` встречается только при чтении ячейки `float`, записи переменной `float` и заполнении полосы.
- Слоты виджетов: числовые `0..Wn`, строки `Wn..Wn+Ws` (генератор кладёт номер в `input` виджета);
  `DisplayPlan.string_widgets`; текст слота читается `input_text(P + Wn + k)`, несоединённый вход — пустая строка.
- Проверка типов v2 (`check_v2_types`) для блоков-дисплеев не требует портов `float`/`int` в `block.toml` под
  дополнительные слоты ни у входов, ни у выходов.

## Виджет `disp_string`
`library/disp_string/` (`block.toml`, `docs.md`): вход `in: string`, параметры как у `disp_text` (шрифт,
экран, x/y/w/h). Генератор, проверка (`check/display.rs`), конструктор экранов (палитра, предпросмотр),
симуляция, пример.

## Мастер
- `firmware/master-rs/src/board/pulse.rs`: статистика в целых.
- `crab-kernel`: `math` op 4 = `fmodf`, `ABI_VERSION = 5`; мастер ESP32 и C3 пересобрать.

## Риски
- Пользовательские блоки (`user_library/lowpass`, `Мои блоки/*`) перестанут собираться до пересборки — это
  решение 1а; сообщение должно называть блок и что делать.
- Округление меню в целых может отличаться от прежнего вывода на последнем знаке — сверка снимками.
- Бенч: AOT-шум ±25 %, сравнивать медиану нескольких заливок.
