# План: микроядро `crab-kernel`, WAMR на плате, Rust-мастер

Спека: `spec.md`. Замеры wasm3 и wasmi: `specs/wasm-on-mcu/plan.md`, раздел «wasmi `no_std` против wasm3 на ESP32-C3».

## 0. Прототип WAMR на C3 (решение о Rust-мастере)
- `specs/wasm-on-mcu/proto/wamr-c3/`, вне workspace, по шаблону `proto/wasmi-c3`: те же модули
  (blink, counter, thermostat17, selftest42, selftest107), тот же вывод в USB-консоль.
- Основа: ESP-IDF (`idf.py` или `esp-idf-sys` через cargo) + WAMR как компонент ESP-IDF; два режима —
  классический/быстрый интерпретатор и AOT (`wamrc --target=riscv32 --cpu=generic-rv32 --target-abi=ilp32`).
- AOT-образ кладём в раздел флеша и выполняем на месте (XIP: `--xip` / `--enable-indirect-mode`); в ОЗУ только
  линейная память, глобалы и стек.
- Замеры: куча на модуль, шаг, загрузка/замена (+ дрейф кучи за 1000 замен), размер AOT-образа против `.wasm`,
  шаг с программной проверкой границ и без неё (`--bounds-checks=1/0`), размер прошивки. Wi-Fi прибавляем расчётом
  (≈ 54 КБ), как для wasmi.
- Итог — строки WAMR-интерп и WAMR-AOT в таблице `wasm-on-mcu/plan.md` и вывод «да/нет» по Rust-мастеру.

## 1а. Упрощённая аренда в C++-мастере (ответ 9–10)
- Мастер запоминает, какие пины модуль занял через `gpio_write`/`pwm_write` (и `gpio_read` с подтяжкой): таблица
  `g_pins[64]` «пин → слот, вид, on_fault». Первый модуль держит пин; второй пишущий получает запись в журнал
  (запись не блокируется). При trap, зависании, `del` и `reset` пины переводятся в безопасное состояние до
  освобождения слота. Замена (`put`, `swap`) пины не трогает; если не запустилась ни новая, ни прежняя версия —
  безопасное состояние. Команда `pins` показывает таблицу.
- Безопасное состояние по умолчанию: цифровой выход 0, ШИМ стоп (скважность 0, канал отключён, вывод LOW), вход без подтяжки.
- Блоки выходов (`digital_out`, `pwm_out`) получают параметр `on_fault` (int: 0 — выключить, 1 — включить, 2 — держать).
  Эмиттер передаёт его в битах 9–10 номера пина (бит 8 — подтяжка), уровень физический — инверсия уже учтена.
  Значение 0 (с учётом инверсии — низкий уровень) не добавляет битов: такие модули идут на старом мастере; иначе модулю нужна возможность
  `on_fault` (в `needs`, мастер сообщает её в `modcaps`). Тот же параметр позже читает `Lease` в Rust-мастере.

## 1. `crab-kernel` (ПК, no_std + alloc)
Новый крейт `crates/crab-kernel`, без GUI, arduino-cli и сети:
- `Handle { index: u16, generation: u16 }`, `SlotMap<T>` — модули, подписки, таймеры. Устаревшая ссылка → `None`.
- `Bus` — перенос правил `crab-sim::bus` (топики «состояние»/«событие», очередь на модуль, счёт потерь).
- `Resources`: трейт `Hal` (gpio, ШИМ, АЦП, UART…) и `Lease<R>` с `Drop`, который переводит ресурс в безопасное
  состояние (по умолчанию из ответа 10, либо `on_fault` блока). Аренда записана за `Handle` модуля; выгрузка/trap
  снимает все аренды модуля.
- Трейт `Engine` (`load`, `call_step`, `call_on_message`, `resume`, `memory`) и бэкенд `engine-wasmi` (фича).
  Бэкенд WAMR — этап 3, через FFI, за той же фичей-трейтом.
- Жизненный цикл: `load` → `run_quantum` → `swap` (новый экземпляр готов → аренды передаются → старый удаляется)
  → `unload`.
- `crab-sim` переходит на ядро; его нынешние тесты — эталон поведения. Хост-функции `crab.*` переезжают в ядро
  одним списком с правами (сейчас их разбирает `parsePerms` в мастере и отдельно `crab-sim`).

## 2. Fuel в эмиттере `crab-codegen`
- В WASM-эмиттере (`crates/crab-codegen/src/wasm/`) глобал-счётчик; на каждом обратном переходе цикла и в начале
  `step` — вычитание и при нуле вызов импорта `crab.yield`.
- Хост `crab.yield`: на ПК (wasmi) — приостановка через resumable-вызов; на плате — блокировка задачи модуля до
  следующего кванта (FreeRTOS). Так одно и то же работает в интерпретаторе и в AOT.
- Версия ABI модуля поднимается (v4, принято); загрузчик отклоняет старую с понятной ошибкой «пересоберите модуль»,
  редактор при заливке пересобирает модули сам.

## 3. Rust-мастер на ESP-IDF (этап 0 → «да, с поправкой»)
- `firmware/master-rs/` (вне workspace, свой тулчейн): `esp-idf-svc` + `crab-kernel` + бэкенд WAMR (FFI к
  компоненту ESP-IDF). WAMR в двух режимах по модулю: AOT с XIP (по умолчанию) и классический интерпретатор
  (флаг в заголовке модуля; для больших листов, где XIP упирается в кэш флеша).
- USB-протокол как у C++-мастера: `put`, `list`, `info`, `stats`, `tick`, `del`; формат раздела `crabmod`
  пересчитан под AOT-образы: области переменной длины, раздел ≈ 2,4 МБ, приложение 1,5 МБ. Тесты редактора, что
  гоняют мастер, проходят без правок.
- Редактор: при сборке модуля под плату вызывает `wamrc` и кладёт `.aot` рядом с `.wasm`; `.wasm` остаётся для
  симулятора. `wamrc` в поставку не входит: при первой сборке AOT-модуля скачивается с релиза WAMR (фиксированная
  версия, проверка SHA-256) в кэш инструментов; путь можно задать вручную в настройках инструментов.
- Сначала C3 (обычный тулчейн), потом ESP32 (Xtensa, `espup`).
- Режим листа (решения 14–18 спеки): свойство листа `speed = "fast" | "normal" | "background"` в `logic.toml`
  (по умолчанию `normal`; в интерфейсе «Быстрый / Обычный / Фоновый»). Режим исполнения пишется флагом в заголовок
  модуля в `crabmod`, мастер держит листы обоих режимов. Перед заливкой `crab-build` считает место под `.aot`
  (свободно в `crabmod` по `info` мастера + новые образы) и раскладывает: `fast` — только AOT, иначе ошибка;
  при нехватке переводит в интерпретатор сначала `background`, затем `normal` по убыванию периода и возрастанию
  оценки шага. Оценка шага до/после — по коэффициентам замеров (AOT против interp) и сравнивается с периодом листа.
  Итог — одно предупреждение на заливку (диалог редактора; галочка ставит `background`), то же жёлтым в панели
  проверки по фоновой сборке; CLI печатает его, `--require-aot` превращает в ошибку. `list`/`info` мастера
  отдают режим листа → окно состояния платы: «ускорен» / «без ускорения».
- Сборка под AOT: эмиттер выводит обёртку-функцию на каждый импорт (вывод только для AOT, interp-модуль без них —
  иначе interp −25…30 %); хост регистрирует raw-нативы. Значит, `.wasm` для AOT и для interp — разные сборки
  одного листа; симулятор берёт interp-вариант.

## 4. Сеть Rust-мастера
- Wi-Fi и MQTT — `esp-idf-svc` (`EspWifi`, `EspMqttClient`); настройки едут с модулями (решение «настройки едут
  с блоками»).
- Ethernet: W5500 по SPI (`esp-idf` драйвер `esp_eth` с `w5500`) и встроенный EMAC ESP32 (LAN8720, IP101 и др.).
  Выбор — параметрами блока `ethernet`, как сейчас.

## 5. Решение о замене C++-мастера
Когда Rust-мастер проходит те же тесты на железе и по памяти не хуже — делаем его мастером по умолчанию,
C++-мастер остаётся на одну версию как запасной.

## Затронутые места
`firmware/master` (C++: упрощённая аренда), блоки выходов в `library/` (`on_fault`),
`crates/crab-kernel` (новый), `crates/crab-sim`, `crates/crab-codegen/src/wasm/`, загрузчик модулей в редакторе,

## Риски
- **WAMR на ESP32-C3 с XIP** — снят этапом 0: `--xip` работает, нужен перевод указателей функций на шину команд
  (`shim_aot_to_ibus` в прототипе). Новый риск — **скорость XIP**: код листа читается из флеша через кэш 16 КБ,
  шаг ≈ размер кода / 20 Б/мкс; на больших листах AOT медленнее интерпретатора WAMR (2,6 мс против 1,8 на 107 блоков).
  Поэтому на плате два режима по модулю: AOT с XIP по умолчанию и классический интерпретатор.
- **Размер AOT-образа** ≈ 4–6 × `.wasm` (≈ 500 Б на блок): нынешний `crabmod` (области по 64 КБ) вмещает лист
  ≈ 130 блоков. Для Rust-мастера: приложение 1,5 МБ, `crabmod` ≈ 2,4 МБ, области переменной длины.
- **Цена проверки границ** — снят: шаг +0…5 %, код +6…30 %; проверку оставляем включённой.
- **Fast-interp WAMR портит кучу** на thermostat17 (не разобрано) — используем классический интерпретатор.
- **`wamrc` = LLVM**: 20 МБ в архиве, 48 МБ распакованный — снят ответом 11 (скачивание при первой сборке и кэш);
  остаётся зависимость от доступа к GitHub при первой AOT-сборке (запасной путь — интерпретатор и ручной путь).
- **Два тулчейна** (C3 обычный, ESP32 `espup`) и сборка ESP-IDF через cargo: долгая первая сборка, сложнее CI.
- **Переход ABI v4** ломает старые модули на плате — нужен понятный отказ и пересборка из редактора.
- **Объём работы** Rust-мастера (веб-страница, Modbus, расширители, сохранение во флеш) — переносить по очереди;
  до паритета C++-мастер остаётся основным.
