# Драйверы железа в WASM — план

## Как `block.wasm` попадает в модуль листа

Драйвер **вклеивается в модуль листа** при генерации (`crab-codegen/src/wasm/driver.rs`), а не грузится на плате
отдельным экземпляром: отдельный экземпляр WAMR стоит страницу памяти (64 КБ) и требует `MULTI_MODULE`, которого в
мастере нет. Вклейка:

- функции, типы, глобали и данные драйвера дописываются в модуль; индексы функций, типов и глобалей сдвигаются;
- память драйвера — **окно** в памяти модуля (`base`): ко всем `load`/`store` добавляется `base` в поле `offset`
  (действующий адрес = адрес + `offset`), активные сегменты данных сдвигаются на `base`. Размер окна — экспорт
  `__heap_base` (у Rust и clang он есть), иначе начальный размер памяти модуля. Окна берутся из той же памяти, что
  строки (`mem_top`), с выравниванием 16;
- на каждый экземпляр блока — своя копия функций (база окна зашита в `offset`) и свои глобали;
- импорты драйвера заменяются вызовами сгенерированных прокладок (на экземпляр): `crab.input/param` читают `f64` из
  ячеек экземпляра (постоянные параметры лежат там с начала — сегмент данных), `crab.output` пишет туда же,
  `crab.log` идёт в `crab.log` мастера, функции `bus.*` — в один импорт `crab.bus(op, a, b, c, d) -> i32`,
  с `base`, прибавленным к указателям;
- `memory.copy/fill` берут адреса со стека — их заменяют вызовы помощников, прибавляющих `base`;
- отклоняются с понятной ошибкой: таблицы и `call_indirect`, `memory.grow`/`memory.size`, пассивные сегменты,
  `start`, импортированные глобали/память, неизвестные импорты, несколько памятей, окно больше 32 КБ.

В шаге модуля драйвер вызывается на месте блока: входы и параметры → `f64` в ячейки, `step(dt)`, выходы из ячеек →
порты (`i32`/`f32`, как у остальных блоков). В `init` модуля: заявки ресурсов (`bus` op 0), закрытие заявок (op 1),
затем `init` драйверов. Тем же путём в модуль попадают и простые пользовательские блоки с `block.wasm` без `bus.*`.

## ABI драйвера (то, что импортирует автор)

`crab.input(i) -> f64`, `crab.param(i) -> f64`, `crab.output(i, f64)`, `crab.log(ptr, len)` — как у симуляции.
`bus.gpio_mode(pin, mode)`, `bus.gpio_read(pin)`, `bus.gpio_write(pin, level)`; `bus.i2c_open(sda, scl, hz)`,
`bus.i2c_write(addr, ptr, len)`, `bus.i2c_read(addr, ptr, len)`, `bus.i2c_write_read(addr, wptr, wlen, rptr, rlen)`;
`bus.uart_open(port, tx, rx, baud)`, `bus.uart_write(port, ptr, len)`, `bus.uart_read(port, ptr, cap)`;
`bus.micros()`, `bus.delay_us(us)` (не больше 100 мкс); `bus.spi_open(sck, mosi, miso, hz)`,
`bus.spi_transfer(cs, ptr, len, mode)`; `bus.ow_reset(pin)`, `bus.ow_write/ow_read(pin, ptr, len)`,
`bus.ow_read_bit(pin)`, `bus.ow_write_bit(pin, bit)`. Все `-> i32`: ≥ 0 — успех/значение, −1 — ресурс не заявлен,
−2 — ошибка шины (NACK), −3 — тайм-аут, −4 — плохие аргументы.

## Мастер (`firmware/master-rs`)

Импорт `crab.bus` (`crab-kernel/src/abi.rs`, право `bus`, возможность мастера `bus` в `MODCAPS`/`MASTER_CAPS`).
Заявки модуля: выводы (op 0, вид 1), адреса I²C (вид 2), порты UART (вид 3); принимаются только до op 1. Каждый
вызов проверяет вывод/адрес/порт по заявкам модуля (`src/bus_cfg.rs`, тесты на ПК) и по выводам чипа (флеш, USB).
I²C — один порт (`I2C0`) на плату, выводы задаёт первый `i2c_open`; UART — `UART1`/`UART2`. C++-мастер `bus` не
получает: редактор не зальёт такой модуль и скажет почему.

## Ядро, симуляция, проверка

- `PortDef.sim` — значение выхода для симуляции (`sim = 21.5` у `[[output]]`); `crab-sim::schema`: блок, чей
  `block.wasm` импортирует `bus.*`, не выполняется, выходы — `sim` (иначе 0). Пробный прогон говорит, что драйвер
  на ПК не выполняется.
- Выводы — параметры `type = "pin"`, общая шина — `bus = "i2c-sda"/"i2c-scl"` (уже есть). Пересечение адресов
  I²C — вне v1 (мастер ответит −1 при чужом адресе).

## Риски

- Ошибка драйвера пишет только в своё окно, но вне окна (в пределах памяти модуля) её ничто не остановит — порча
  чужих данных листа; мастер при этом цел. Отмечено в справке.
- Rust по умолчанию берёт стек 1 МБ: автору надо `-C link-arg=-zstack-size=4096` (в примере и справке).
- Копия функций на экземпляр увеличивает модуль; для 1–3 датчиков приемлемо.
