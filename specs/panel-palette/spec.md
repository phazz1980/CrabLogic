# Спека: палитра элементов щита и подключение по листам

Статус: ответы получены 23.11.2026, план — `plan.md`.

## Цель

Наполнять щит как в EPLAN: слева общий список доступных элементов с картинкой, элемент тащится на
лист; составные элементы (реле, контактор) раскрываются на части (катушка, контакты), и каждую
часть можно поставить отдельно. Связи части задаются в её свойствах: выбором листа и элемента на
нём; связь на другой лист рисуется ссылкой.

## Сценарии пользователя

1. **Палитра.** Слева — список элементов: автомат, УЗО, предохранитель, рубильник, блок питания,
   контактор, реле, двигатель, нагрузка, клеммник, датчик, кнопка. У каждого — маленькая
   картинка условного обозначения (тот же рисунок, что на листе). Составные (контактор, реле)
   раскрываются: «Катушка», «Контакт». Перетащил на лист — элемент появился там, где бросил.
2. **Катушка.** Брошенная катушка получает имя по листу (`K3.1` — первая на листе 3); имя можно
   сменить в свойствах. В свойствах — куда подключены `A1` и `A2`: сначала номер листа (по
   умолчанию — лист, где стоит катушка), потом выбор из выводов элементов этого листа.
3. **Контакт.** В свойствах — вид: замыкающий (НО), размыкающий (НЗ), перекидной; и катушка,
   которой он принадлежит (список катушек проекта). Под катушкой — таблица его ссылкой, у контакта —
   ссылка на катушку (как сейчас).
4. **Связь на другой лист.** Если вывод подключён к элементу другого листа, провод доходит до
   обрыва, и у обрыва стоит ссылка `/лист.столбец` на ответный конец; на том листе — ответный
   обрыв со ссылкой обратно.
5. Дерево проекта (что уже есть в щите) остаётся ниже палитры: найти, выбрать, удалить.

## Критерии готовности (проверяемые)

- Палитра показывает все виды элементов с картинкой; перетаскивание создаёт устройство на том
  листе и в том месте, где отпущено (тест «бросок → устройство на листе»).
- Катушка, брошенная на лист N, получает имя `K<N>.<k>`; переименование сохраняет раскладку и связи.
- `A1`/`A2` выбираются «лист → элемент → вывод»; выбор создаёт провод, он есть в перечне проводов.
- Перекидной контакт: символ с тремя клеммами (`11-12-14`), в таблице под катушкой и в перечне.
- Провод между листами рисуется двумя обрывами со взаимными ссылками (тест на обе ссылки).
- Старые проекты открываются без изменений вида.
- Справка `help/18-panel.md` обновлена.

## Вопросы пользователю

1. **Палитра и дерево.** Палитра сверху слева, дерево проекта под ней (как в EPLAN: «Навигатор
   устройств» + «Символы»)? Или палитра вместо кнопок «+» в группах дерева, а дерево остаётся?
2. **Генератор.** Сейчас листы строит генератор: силовая цепочка по «Питается от», катушка по
   привязке к выходу платы. Как быть с ним?
   а) остаётся: брошенное вручную встаёт рядом, генератор дорисовывает остальное (сейчас так);
   б) ручной режим проекта: генератор ставит элементы один раз, дальше всё руками;
   в) генератор только для силовой части, лист управления — только руками.
3. **Части отдельно.** Контакт, брошенный без катушки, — «свободный», пока не выбрана катушка
   (метка `[✕]` в дереве)? Катушка, брошенная отдельно, создаёт новое реле/контактор целиком?
4. **Выбор подключения A1/A2.** Список элементов листа — все выводы всех элементов листа плюс шины
   (`+24V`, `0V`, `L1`…) и выводы платы (`A1:IO5`)? Подключение к шине тоже ссылкой на шину?
5. **Перекидной контакт.** Клеммы `11-12-14` (общий 11, НЗ 12, НО 14) — так? Нужен ли он у
   автомата/УЗО или только у контактора и реле?
6. **Имя по листу.** Нумерация `K3.1, K3.2` по порядку броска или по столбцам листа слева
   направо (как «Обозначения по листам» сейчас)? При переносе катушки на другой лист имя меняется
   само или только по кнопке?

## Ответы пользователя (23.11.2026)

1. Палитра **заменяет** кнопки «+» в группах дерева; дерево проекта остаётся (найти, выбрать, удалить).
2. **б)** Генератор раскладывает элементы один раз, дальше всё руками: ручное положение не
   перебивается генератором, новые элементы приходят только из палитры.
3. Катушка реле из палитры создаёт **только катушку** (реле без силовых контактов); к ней
   привязываются контакты. Контакт без катушки — свободный, с меткой `[✕]` в дереве, пока в его
   свойствах не выбрана катушка.
4. В списке подключения `A1`/`A2` — выводы элементов листа, **шины** (`+24V`, `0V`, `L1`…) и выводы
   платы. Вывод платы — клемма контроллера щита (ESP32, на листе управления рамка канала `-A1:IO26`):
   так катушка получает сигнал выхода программы. Решение архитектора: выбор вывода платы = привязка
   к тегу этого вывода (как поле «Катушка: выход платы» сейчас).
5. Перекидной контакт — пока только у реле; клеммы `11-12-14` (общий, НЗ, НО).
6. Имя по листу — по порядку броска: `K3.1`, `K3.2`…
7. Катушку перенесли на другой лист — редактор **предлагает** сменить имя (не меняет сам).

## Уточнение режима «б» (24.11.2026)

Пользователь выбрал **смешанный** вариант вместо заморозки: генератор рисует всё, что руками не
трогали; поставленное вручную важнее генератора (катушка, датчик, кнопка, контакт на листе
управления); автоматические провода, которые генератор не нарисовал (к частям, перенесённым
руками), рисуются общим путём, как ручные, а между листами — обрывами со ссылками. Вид щита
меняется только там, где что-то переносили. Силовые цепочки пока остаются за генератором.
