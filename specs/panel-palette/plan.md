# План: палитра элементов щита и подключение по листам

## Затронутое

- Модель реле и контактов — из `specs/panel-relay-contacts` (сделано другой сессией 23.11.2026):
  контакт реле — `Aux` с `of = <реле>`, вид `ContactForm::Changeover` (`11-12-14`); новое реле —
  катушка и список контактов, без «Полюсов» и «Нагрузки»; контакт реле может коммутировать
  нагрузку («Питается от» у нагрузки). Наш вариант этапа 1 (`Co`, `poles = 0`) снят, сохранён в
  ветке `backup/panel-palette-stage1`; из него перенесены широкая катушка, рисунок перекидного
  контакта, «Контакты без катушки».
  Концы ручного провода: кроме `DEV:pin` — шина `bus:<имя>` (`bus:+24V`, `bus:0V`, `bus:L1`).
  `Panel::links` остаётся единственным местом ручных проводов (провод `A1`/`A2` катушки — тоже link).
- `crab-core/src/panel_edit.rs`: `connect(project, end, target)` — заменить провод на выводе
  (старый link с этого вывода удаляется); вывод платы → `rebind_device` (как в `rewire`);
  `next_sheet_name(panel, layout, letter, sheet)` — `K3.<k>` по порядку броска.
- `crab-core/src/panel_layout.rs`: `PanelLayout.manual: bool` (режим «б»). При `manual` генератор
  не ставит устройства сам: каждое устройство либо в `placed`, либо его нет на листах.
  Заморозка `freeze(document)` пишет в `placed` места всех символов, нарисованных генератором.
- `crab-schematic`:
  - символ перекидного контакта; строка таблицы под катушкой для него;
  - обрыв провода между листами: link, концы которого на разных листах, рисуется до края цепи
    обрывом со стрелкой и ссылкой `/лист.столбец` на ответный конец (оба листа, двухпроходная
    сборка — как `coil_at`); то же для провода к шине, которой нет на листе;
  - картинка элемента для палитры: `symbol_preview(kind, part) -> Vec<Op>` из тех же функций
    рисования символов (один источник для листа и палитры).
- `crab-editor/src/panelview.rs`:
  - палитра: группы как в дереве, строка = картинка + название, составные раскрываются
    (реле → «Катушка», «Контакт»); кнопки «+» в группах дерева убираются;
  - бросок из палитры: новое устройство (`free`), имя по листу для катушки, `place(...)` в точку
    броска, при первом броске — `freeze` и `manual = true` (одним шагом отмены);
  - свойства катушки: имя, `A1`/`A2`: «лист» (по умолчанию свой) → «элемент:вывод» из листа
    (выводы символов, шины листа, выводы платы); свойства контакта: вид, катушка;
  - перенос катушки на другой лист → предложение «Переименовать в K5.2?».

## Формат данных

Новые поля необязательные (`serde(default)`), старые проекты читаются как есть: `manual = false` —
генератор работает как сейчас, вид не меняется. Режим «б» включается первым броском из палитры.

## Риски

- **Заморозка.** Провода генератора (силовые столбцы, лестница) после заморозки рисуются от
  моделей связей (`load`, `bind`, links) по местам символов; если символ унесли на другой лист,
  провод должен уйти в обрыв. Это общий путь с п. «обрыв» — делать его до заморозки.
- **Две правды о катушке**: привязка `bind` (выход платы) и провод `A1` → вывод платы. Решение:
  вывод платы в списке = `bind`, отдельного link к плате не создаём.
- Объём: задачу режем на этапы, каждый этап — рабочий редактор и зелёные тесты.
