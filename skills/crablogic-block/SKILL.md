# Свой блок в CrabLogic

Блок — папка `<тип>/` с тремя файлами:
- `block.toml` — название, входы, выходы, параметры ([`reference/block-toml.md`](reference/block-toml.md));
- `block.wasm` — код блока: модуль WASM, собранный из Rust ([`reference/wasm-api.md`](reference/wasm-api.md));
- `docs.md` — описание по-русски (показывается в справке, по нему ИИ подбирает блоки).

Мастер на Rust вклеивает `block.wasm` в модуль листа; на компьютере логика выполняется в симуляции
по-настоящему, а драйвер (зовёт `bus.*`) — нет: его выходы берут значения `sim`.

## Как запускать `crablogic`

`crablogic.exe` лежит в папке программы рядом с `crablogic-editor.exe` (`<папка программы>` — та, где
`library/` и `user_library/`). Нет его там — спроси у пользователя путь; в репозитории исходников вместо него
`cargo run -q -p crab-cli --`. Флаг `--library` ставится **перед** командой:

```
crablogic --library <папка программы>/library block check <папка блока>
crablogic --library <папка программы>/library check <папка проекта>
crablogic --library <папка программы>/library gen-wasm <папка проекта>
```

Сборка блока в PowerShell: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1` (так скрипт
запустится и там, где запуск скриптов запрещён политикой).

Проверка после правки: в Claude Code она идёт сама (хуки в `.claude/settings.json` папки программы), иначе —
`powershell -NoProfile -ExecutionPolicy Bypass -File skills/crablogic-block/hooks/check.ps1 <папка блока>`.
Ошибку, которую вернула проверка, исправь сразу, не продолжая работу.

## Порядок работы

1. **Выясни задачу** (чего нет — спроси одним сообщением): что блок получает и выдаёт (типы `bool`,
   `int`, `float`; строк нет), какие настройки, помнит ли состояние. Для датчика: шина, адрес, выводы
   по умолчанию, протокол — **из даташита**; ссылку или название документа запиши в `docs.md`. Если даташита
   нет, а пользователь разрешил по памяти — так и напиши в `docs.md`: «протокол по памяти, с даташитом не
   сверен, на железе не проверено».
2. **Выбери образец** из [`examples/`](examples/) и скопируй его целиком в рабочую папку
   `<папка программы>/blocks_src/<тип>/` (исходники блока; в библиотеку попадёт только готовый блок):
   - [`window_check`](examples/window_check/) — логика без памяти (значение в окне low…high);
   - [`run_hours`](examples/run_hours/) — логика с памятью и параметром (моточасы, число пусков);
   - [`bh1750`](examples/bh1750/) — драйвер датчика на I²C (освещённость), чтение по периоду без ожидания.

   В образце: `src/lib.rs`, `Cargo.toml`, `build.ps1`, проект `project/` с блоком в `project/library/<тип>/`.
   Пути в README образцов даны от `<папка программы>`.
3. **Переименуй** везде одинаково (строчная латиница, `_`): папку образца, папку блока
   `project/library/<тип>/`, `type` в `block.toml`, `name` в `Cargo.toml`, тип блока в `project/logic.toml`.
   `build.ps1` берёт имя из названия папки образца. Не занимай имя встроенного блока.
4. **Напиши `block.toml`**. Номера портов и параметров в коде — их порядок в `block.toml` с нуля:
   заведи в `lib.rs` константы (`const I_RUN: i32 = 0;`) и держи их в том же порядке.
5. **Напиши `src/lib.rs`** по раскладке образца: поведение — обычные функции или структура состояния без
   `unsafe`; обвязка WASM (импорты, `init`, `step`, `#[panic_handler]`) — в `mod wasm` под
   `#[cfg(target_arch = "wasm32")]`; состояние экземпляра — один `static mut` этой структуры. `step` **никогда
   не ждёт**: время копи из `dt_ms`. Короткие циклы с известным числом шагов (CRC по 6 байтам, сортировка трёх
   чисел) можно; нельзя циклы, которые ждут ответа устройства. Драйвер на ошибку шины ставит `ok = false` и
   пробует снова через период. Входу ставь `default`, если без провода у него есть разумное значение
   (сброс — `false`); вход, без которого блок бессмыслен, оставь без `default` — схема потребует провод.
   Что выдавать в первом цикле (до измерения, до накопления), реши и опиши в `docs.md`.
6. **Проверь поведение на ПК**: в `src/lib.rs` — `#[cfg(test)] mod tests` с проверками формул, граничных
   значений и сброса (как в `window_check`, `run_hours`); `cargo test` → все `ok`. Обмен с шиной так не
   проверить — у драйвера тестируй разбор ответа (пересчёт, CRC).
7. **Собери**: `build.ps1` (нужна цель `wasm32-unknown-unknown`; если `rustup target list --installed` её
   не показывает — спроси пользователя, прежде чем ставить).
8. **Проверь блок**: `crablogic block check <папка блока>` → «Ошибок нет». Ошибки — по
   [`reference/errors.md`](reference/errors.md), правь и повторяй.
9. **Проверь в проекте**: поправь `project/logic.toml` под свои порты, затем `check` и `gen-wasm` проекта
   — без ошибок, «Модуль «sheet1»: … байт».
10. **Напиши `docs.md`** (образец — в примере): что делает, таблица входов/выходов/параметров с единицами,
   как ведёт себя при ошибке и до первого измерения, подключение и адрес (драйвер), «не проверено на
   железе», если не проверено.
11. **Установи блок**, когда пользователь согласен: скопируй из `project/library/<тип>/` **только**
    `block.toml`, `block.wasm`, `docs.md` (и `images/`, если есть) в
    `<папка программы>/user_library/Мои блоки/<тип>/` — блок появится во всех проектах (набор «Мои блоки»,
    его `pack.toml` не трогай). Для одного проекта-папки — в `<проект>/library/<тип>/`. `src/`, `target/`,
    `Cargo.*`, `project/` остаются в `blocks_src/`. Проверь установленную копию `block check` и пройди
    [`checklist.md`](checklist.md).

## Нельзя

- C++: `esp32.cpp.tmpl`, `native.cpp`, библиотеки Arduino — мастер на Rust их не исполняет.
- Строковые порты и параметры, `memory.grow`, `alloc`, `dyn`/указатели на функции, импорты не из
  `crab.*`/`bus.*`, данные больше 32 КБ.
- Ожидание ответа устройства внутри `step` (цикл «пока не готово»); `delay_us` больше 100 мкс.
- Правка файлов программы: `crates/`, `library/`, `firmware/`.
- Перестановка портов или параметров в готовом блоке, которым уже пользуются: проекты ссылаются на имена,
  код — на номера.
- Придумывать регистры и адреса датчика: нет даташита — спроси (или явно пометь «по памяти», см. шаг 1).
